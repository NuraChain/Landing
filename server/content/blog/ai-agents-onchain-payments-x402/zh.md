HTTP 从九十年代初就带着一个叫 `402 Payment Required` 的状态码。它被留给一个始终没到来的未来，三十年里对它最正确的处理就是什么都不做。到了 2026 年，它忽然开始承重：x402 用这个响应让客户端为单次请求付费，用稳定币结算，不需要账号，也不需要 API key。

## 机制，三步

1. 客户端请求某个资源。服务器返回 `402`，附带一段结构化 JSON，写明价格和付款去向。
2. 客户端在链上付款，带着付款凭证重试请求。
3. 服务器验证后返回响应。

整个协议就这些。没有注册，没有账期，没有存档的卡，也没有起步金额。需要一次推理或一页数据的调用方，就只为一次推理或一页数据付费。

## 为什么是现在

因为调用方不再是人。自主代理填不了注册表单，拿不了公司卡，也等不到月底发票结清。但它可以持有私钥并签一笔转账，而按请求计价是唯一适配「每小时做上千个小决定」这种东西的计费模型。

规模也不再是假设。2025 年 10 月到 2026 年 1 月的一次为期十四周的 beta 中，一千多名参与者创建了超过 9,500 个代理，它们之间执行了约 187,000 笔自主交易。

## 这对一条链提出什么要求

三条属性，没一条华丽。

- **交易便宜。** 一笔不到一分钱的付款，不能比它买的东西还贵。
- **快速终局。** 请求正在等着。以分钟计的结算窗口等于超时。
- **稳定的计价单位。** 没人会用一个在重试之前就波动百分之十的资产给 API 调用定价。

任何满足这三点的 EVM 网络都能承载这类流量；交易本身没有任何特别之处。[连接 Nura Chain RPC](/blog/connect-to-nura-chain-rpc) 用的就是代理会用的那套 JSON-RPC，而这里的区块大约每三秒出一个。

## 上线之前必须做对的事

持有私钥的代理，是一个无人值守的签名者。就按这个标准对待它。

- **只给薄薄一层资金。** 一天工作量大小的热余额，有意识地补充，而不是一个金库。
- **给它设边界。** 带花费上限和有效期的会话密钥——这正是智能账户如今让它变得可行的，参见 [EIP-7702 与智能账户](/blog/eip-7702-smart-accounts)。
- **记录每一笔付款。** 一个默默花钱的代理，是事后没法审计的代理。
- **把私钥和提示词分开。** 代理读到的任何东西都可能试图指挥它。花费上限是唯一一个不会跟你争辩的控制项。

代理支付真正有意思的地方不是机器能付钱，而是按请求计价终于有了一层结算在下面托着。
