یک dApp، برنامه وبی معمولی است با یک ویژگی غیرمعمول: هرگز کلید کاربر را نگه نمی‌دارد. از یک زنجیره می‌خواند، و وقتی می‌خواهد چیزی را تغییر دهد از یک کیف پول می‌خواهد امضا کند. هر چه در پی می‌آید از همین تقسیم نتیجه می‌شود.

## دو نیمه

خواندن و نوشتن دو مسیر جداگانه‌اند، و یکی‌گرفتنشان رایج‌ترین اشتباه ساختاری است.

**خواندن** از اتصال RPC خودتان می‌گذرد. به کیف پول نیازی ندارد، پیش از آنکه کسی وصل شود کار می‌کند، و باید تا جای ممکن رابط شما را ترسیم کند. موجودی‌ها، وضعیت قرارداد، قیمت‌ها، تاریخچه — همه‌اش عمومی است.

**نوشتن** از کیف پول کاربر می‌گذرد. به تأیید او نیاز دارد، می‌تواند رد شود، و تنها بخشی است که اصلاً به اتصال نیاز دارد.

اول مسیر خواندن را بسازید. dAppی که تا وصل‌شدن کسی صفحه سفید نشان می‌دهد، dAppی است که به هر کسی که دارد می‌سنجد آیا وصل شود یا نه، صفحه سفید نشان می‌دهد.

## خواندن

از یک کلاینت عمومی که به نقطه‌پایانی نشانه رفته استفاده کنید، دقیقاً مثل [اتصال به RPC نورا چین](/blog/connect-to-nura-chain-rpc):

```javascript
import { createPublicClient, defineChain, http } from 'viem';

export const nura = defineChain({
    id: 1020,
    name: 'Nura Chain',
    nativeCurrency: { name: 'Nura', symbol: 'NURA', decimals: 18 },
    rpcUrls: { default: { http: ['https://rpc.nurachain.net'] } },
    blockExplorers: {
        default: { name: 'Nura Explorer', url: 'https://explorer.nurachain.net' }
    }
});

export const publicClient = createPublicClient({ chain: nura, transport: http() });
```

این شیء، تعریف یگانه شبکه برای کل برنامه است. به‌جای تکرار مقادیر، همه‌جا واردش کنید.

## وصل‌کردن کیف پول

کیف پول مرورگری یک provider مطابق EIP-1193 تزریق می‌کند. سازوکار امروزی کشف، EIP-6963 است که هر کیف پول نصب‌شده را اعلام می‌کند به‌جای آنکه سر یک متغیر سراسری دعوا شود — اگر ممکن است بیش از یک کیف پول حاضر باشد، ارزش استفاده دارد. کمینه‌اش:

```javascript
async function connect() {
    const provider = window.ethereum;

    if (provider === undefined) {
        throw new Error('No wallet found');
    }

    const [account] = await provider.request({ method: 'eth_requestAccounts' });

    return account;
}
```

این را از یک کلیک صدا بزنید، نه هنگام بارگذاری صفحه. dAppی که همان لحظه بازشدن صفحه پنجره کیف پول را بالا می‌آورد، dAppی است که کاربران می‌بندندش.

## رساندنشان به شبکه درست

این همان گامی است که بیشتر راهنماها از آن می‌گذرند، و جایی است که کاربران واقعی گیر می‌کنند. کیف پول وصل‌شده ممکن است روی هر زنجیره‌ای باشد. از آن بخواهید سوئیچ کند، و حالتی را که هرگز نام نورا چین را نشنیده هم مدیریت کنید:

```javascript
const NURA_HEX = '0x3fc';

async function ensureNura(provider) {
    try {
        await provider.request({
            method: 'wallet_switchEthereumChain',
            params: [{ chainId: NURA_HEX }]
        });
    } catch (error) {
        // 4902: the wallet does not know this chain yet. Offer to add it, then
        // the switch above succeeds on the next attempt.
        if (error.code === 4902) {
            await provider.request({
                method: 'wallet_addEthereumChain',
                params: [{
                    chainId: NURA_HEX,
                    chainName: 'Nura Chain',
                    nativeCurrency: { name: 'Nura', symbol: 'NURA', decimals: 18 },
                    rpcUrls: ['https://rpc.nurachain.net'],
                    blockExplorerUrls: ['https://explorer.nurachain.net']
                }]
            });
        } else {
            throw error;
        }
    }
}
```

`0x3fc` همان ۱۰۲۰ به هگز است و کیف پول‌ها شکل هگز را می‌خواهند. شاخه `4902` همان چیزی است که «با کلیک هیچ اتفاقی نمی‌افتد» را به یک تجربه نخستین‌بار کارآمد تبدیل می‌کند — همان درخواستی است که در [افزودن نورا چین به کیف پول](/blog/add-nura-chain-to-your-wallet) توضیح داده شد، اما این‌بار صفحه شما صادرش می‌کند نه دست کاربر.

به تغییرها هم گوش بدهید، چون کاربر می‌تواند پشت سر شما شبکه یا حساب را عوض کند:

```javascript
provider.on('chainChanged', () => window.location.reload());
provider.on('accountsChanged', (accounts) => setAccount(accounts[0] ?? null));
```

بارگذاری دوباره روی `chainChanged` خام است اما درست: تضمین می‌کند هیچ وضعیت کهنه وابسته به زنجیره باقی نماند.

## فرستادن یک تراکنش

```javascript
import { createWalletClient, custom, parseEther } from 'viem';

const walletClient = createWalletClient({
    chain: nura,
    transport: custom(window.ethereum)
});

const hash = await walletClient.sendTransaction({
    account,
    to: '0xRecipient',
    value: parseEther('1')
});

const receipt = await publicClient.waitForTransactionReceipt({ hash });

if (receipt.status === 'reverted') {
    throw new Error('The transaction was included but reverted');
}
```

دو نکته را ببینید. کلاینت کیف پول می‌فرستد؛ کلاینت عمومی منتظر می‌ماند. و رسیدی با وضعیت `reverted` تراکنشی است که رخ داده، گس خرج کرده و آنچه خواسته شده را انجام نداده — موفق شمردنش خطایی است که کاربران پیدایش می‌کنند.

## حالت‌هایی که واقعاً پیش می‌آیند

همه اینها را مدیریت کنید، چون هرکدام مرتب رخ می‌دهند:

- **کیف پولی نصب نیست.** یک پیوند نشان دهید، نه دکمه‌ای خراب.
- **اتصال رد شد.** کاربر نه گفته. بی‌سروصدا به حالت وصل‌نشده برگردید؛ دوباره درخواست نکنید.
- **شبکه اشتباه.** به‌جای خطا، دکمه سوئیچ پیشنهاد دهید. این بزرگ‌ترین منبع سردرگمی کاربران است.
- **تراکنش در کیف پول رد شد.** شرط خطا نیست. وضعیت در انتظار را پاک کنید و ادامه دهید.
- **در انتظار.** هش و پیوندی به [کاوشگر نورا](https://explorer.nurachain.net) نشان دهید تا خودشان تماشا کنند.
- **برگشت‌خورده.** صریح بگویید. «تراکنش ناموفق» به‌همراه هش، از چرخنده‌ای که هرگز نمی‌ایستد بهتر است.

## چه کارهایی نکنید

- **کلید خصوصی نخواهید.** هرگز، به هیچ دلیلی. dAppی که می‌خواهد از یک صفحه فیشینگ قابل تشخیص نیست.
- **به‌صورت پیش‌فرض مجوز نامحدود توکن نخواهید.** همان مقداری را که واقعاً لازم است تأیید بگیرید. اگر ناچارید مجوز بزرگ بگیرید، در رابط بگویید.
- **به شناسه زنجیره‌ای که در state است اعتماد نکنید.** پیش از فرستادن هر چیز مهمی، از provider بخوانیدش.
- **کل رابط را گروگان اتصال کیف پول نکنید.** بخش نخست را ببینید.
- **در هر رندر از زنجیره نظرسنجی نکنید.** خواندن‌ها را کش کنید و درخواست‌های در پرواز را به اشتراک بگذارید.

## پرسش‌های رایج

### آیا به بک‌اند نیاز دارم؟

برای خواندن یا نوشتن روی زنجیره نه — هر دو مستقیم از مرورگر می‌روند، و همین است که CORS باز نقطه‌پایانی ممکنش می‌کند. بک‌اند برای کارهایی لازم است که زنجیره‌ها در آنها بدند: جست‌وجو، تجمیع، داده بیرون‌زنجیره‌ای.

### می‌توانم از wagmi یا RainbowKit استفاده کنم؟

بله. همان تعریف زنجیره قطعه نخست را به آنها بدهید. آنها بیشتر همان منطق اتصال و سوئیچ شبکه بالا را می‌پوشانند، که ارزش دارد یک‌بار بفهمیدش پیش از آنکه واگذارش کنید.

### چطور موجودی توکن را نشان دهم؟

روی قرارداد توکن `balanceOf` را صدا بزنید و با `decimals()` خودش قالب‌بندی کنید. هرگز تعداد اعشار را فرض نکنید — [ساخت یک ERC-20 روی نورا چین](/blog/create-an-erc-20-token-on-nura-chain) توضیح می‌دهد چرا این فرض دقیقاً اینجا گران تمام می‌شود.

### چطور بدون خرج‌کردن آزمایش کنم؟

مسیرهای خواندن اصلاً پول نمی‌خواهند. برای نوشتن، از حسابی دورریختنی با موجودی کم استفاده کنید و هر نتیجه را روی کاوشگر تأیید کنید.
