dApp एक सामान्य वेब ऐप्लिकेशन है जिसमें एक असामान्य गुण है: यह उपयोगकर्ता की कुंजी कभी नहीं रखता। यह चेन से पढ़ता है, और जब कुछ बदलना चाहता है तो किसी वॉलेट से हस्ताक्षर करने को कहता है। आगे जो कुछ है, वह इसी विभाजन से निकलता है।

## दो हिस्से

पढ़ना और लिखना अलग रास्ते हैं, और इन्हें एक कर देना सबसे आम संरचनात्मक ग़लती है।

**पढ़ना** आपके अपने RPC कनेक्शन से होता है। इसे वॉलेट नहीं चाहिए, किसी के जुड़ने से पहले चलता है, और इसे आपके इंटरफ़ेस का जितना संभव हो उतना बनाना चाहिए। बैलेंस, कॉन्ट्रैक्ट स्थिति, क़ीमतें, इतिहास — सब सार्वजनिक है।

**लिखना** उपयोगकर्ता के वॉलेट से होता है। इसे उनकी स्वीकृति चाहिए, यह अस्वीकार हो सकता है, और यही एकमात्र हिस्सा है जिसे कनेक्शन चाहिए ही।

पहले पढ़ने का रास्ता बनाइए। जो dApp किसी के जुड़ने तक ख़ाली पेज दिखाता है, वह हर उस व्यक्ति को ख़ाली पेज दिखाता है जो तय कर रहा है कि जुड़े या नहीं।

## पढ़ना

एंडपॉइंट पर लगा सार्वजनिक क्लाइंट इस्तेमाल कीजिए, ठीक वैसे जैसे [Nura Chain RPC से जुड़ना](/blog/connect-to-nura-chain-rpc) में:

```javascript
import { createPublicClient, defineChain, http } from 'viem';

export const nura = defineChain({
    id: 1020,
    name: 'Nura Chain',
    nativeCurrency: { name: 'Nura', symbol: 'NURA', decimals: 18 },
    rpcUrls: { default: { http: ['https://rpc.nurachain.net'] } },
    blockExplorers: {
        default: { name: 'Nura Explorer', url: 'https://explorer.nurachain.net' }
    }
});

export const publicClient = createPublicClient({ chain: nura, transport: http() });
```

यह ऑब्जेक्ट पूरे ऐप्लिकेशन के लिए नेटवर्क की एकमात्र परिभाषा है। मान दोहराने के बजाय इसे हर जगह आयात कीजिए।

## वॉलेट जोड़ना

ब्राउज़र वॉलेट एक EIP-1193 प्रोवाइडर इंजेक्ट करता है। खोज का आधुनिक तरीक़ा EIP-6963 है, जो एक वैश्विक चर पर झगड़ने के बजाय हर स्थापित वॉलेट की घोषणा करता है — अगर एक से ज़्यादा वॉलेट मौजूद हो सकते हैं तो यह इस्तेमाल के क़ाबिल है। न्यूनतम रूप:

```javascript
async function connect() {
    const provider = window.ethereum;

    if (provider === undefined) {
        throw new Error('No wallet found');
    }

    const [account] = await provider.request({ method: 'eth_requestAccounts' });

    return account;
}
```

इसे क्लिक से बुलाइए, पेज लोड पर कभी नहीं। जो dApp पेज खुलते ही वॉलेट की खिड़की खोल देता है, उसे उपयोगकर्ता बंद कर देते हैं।

## उन्हें सही नेटवर्क पर लाना

यही वह क़दम है जिसे अधिकांश गाइड छोड़ देते हैं, और यहीं असली उपयोगकर्ता अटकते हैं। जुड़ा हुआ वॉलेट किसी भी चेन पर हो सकता है। उससे स्विच करने को कहिए, और उस हालत को भी सँभालिए जब उसने Nura Chain का नाम ही न सुना हो:

```javascript
const NURA_HEX = '0x3fc';

async function ensureNura(provider) {
    try {
        await provider.request({
            method: 'wallet_switchEthereumChain',
            params: [{ chainId: NURA_HEX }]
        });
    } catch (error) {
        // 4902: the wallet does not know this chain yet. Offer to add it, then
        // the switch above succeeds on the next attempt.
        if (error.code === 4902) {
            await provider.request({
                method: 'wallet_addEthereumChain',
                params: [{
                    chainId: NURA_HEX,
                    chainName: 'Nura Chain',
                    nativeCurrency: { name: 'Nura', symbol: 'NURA', decimals: 18 },
                    rpcUrls: ['https://rpc.nurachain.net'],
                    blockExplorerUrls: ['https://explorer.nurachain.net']
                }]
            });
        } else {
            throw error;
        }
    }
}
```

`0x3fc` हेक्स में 1020 है, और वॉलेट हेक्स रूप ही चाहते हैं। `4902` शाखा वही है जो "क्लिक करने पर कुछ नहीं होता" को कामकाजी पहले अनुभव में बदल देती है — यह वही अनुरोध है जो [अपने वॉलेट में Nura Chain जोड़ना](/blog/add-nura-chain-to-your-wallet) में बताया गया, बस इसे हाथ से नहीं, आपका पेज जारी करता है।

बदलावों को भी सुनिए, क्योंकि उपयोगकर्ता आपकी पीठ पीछे नेटवर्क या खाता बदल सकता है:

```javascript
provider.on('chainChanged', () => window.location.reload());
provider.on('accountsChanged', (accounts) => setAccount(accounts[0] ?? null));
```

`chainChanged` पर पुनः लोड करना भोंडा है पर सही: यह गारंटी देता है कि चेन-विशिष्ट कोई बासी स्थिति बची न रहे।

## ट्रांज़ैक्शन भेजना

```javascript
import { createWalletClient, custom, parseEther } from 'viem';

const walletClient = createWalletClient({
    chain: nura,
    transport: custom(window.ethereum)
});

const hash = await walletClient.sendTransaction({
    account,
    to: '0xRecipient',
    value: parseEther('1')
});

const receipt = await publicClient.waitForTransactionReceipt({ hash });

if (receipt.status === 'reverted') {
    throw new Error('The transaction was included but reverted');
}
```

दो बातें ध्यान दीजिए। वॉलेट क्लाइंट भेजता है; सार्वजनिक क्लाइंट प्रतीक्षा करता है। और `reverted` स्थिति वाली रसीद ऐसा ट्रांज़ैक्शन है जो हुआ, गैस ख़र्च की, और जो कहा गया वह नहीं किया — इसे सफल मानना ऐसा दोष है जिसे उपयोगकर्ता ढूँढ़ निकालेंगे।

## वे स्थितियाँ जो सचमुच आती हैं

इन सबको सँभालिए, क्योंकि हर एक नियमित रूप से होती है:

- **कोई वॉलेट स्थापित नहीं।** लिंक दिखाइए, टूटा बटन नहीं।
- **कनेक्शन अस्वीकृत।** उपयोगकर्ता ने ना कहा। चुपचाप बिना-जुड़ी स्थिति पर लौटिए; दोबारा मत पूछिए।
- **ग़लत नेटवर्क।** त्रुटि के बजाय स्विच बटन दीजिए। उपयोगकर्ताओं की उलझन का यह सबसे बड़ा अकेला स्रोत है।
- **वॉलेट में ट्रांज़ैक्शन अस्वीकृत।** यह त्रुटि नहीं है। लंबित स्थिति साफ़ कीजिए और आगे बढ़िए।
- **लंबित।** हैश और [Nura Explorer](https://explorer.nurachain.net) का लिंक दिखाइए ताकि वे स्वयं देख सकें।
- **वापस हुआ।** साफ़-साफ़ कहिए। हैश के साथ "ट्रांज़ैक्शन विफल" उस स्पिनर से बेहतर है जो कभी नहीं रुकता।

## क्या न करें

- **निजी कुंजी मत माँगिए।** कभी नहीं, किसी कारण से नहीं। जो dApp माँगता है वह फ़िशिंग पेज से अलग नहीं दिखता।
- **डिफ़ॉल्ट रूप से असीमित टोकन अनुमोदन मत माँगिए।** जितना वास्तव में चाहिए उतना ही स्वीकृत कराइए। बड़ी अनुमति चाहिए ही तो इंटरफ़ेस में कहिए।
- **स्टेट में रखी चेन आईडी पर भरोसा मत कीजिए।** कुछ भी महत्वपूर्ण भेजने से पहले प्रोवाइडर से पढ़िए।
- **पूरे इंटरफ़ेस को वॉलेट कनेक्शन पर मत रोकिए।** पहला भाग देखिए।
- **हर रेंडर पर चेन से पोल मत कीजिए।** पठन कैश कीजिए और चालू अनुरोध साझा कीजिए।

## आम सवाल

### क्या मुझे बैकएंड चाहिए?

चेन से पढ़ने या लिखने के लिए नहीं — दोनों सीधे ब्राउज़र से जाते हैं, और यही एंडपॉइंट का उदार CORS संभव बनाता है। बैकएंड उन चीज़ों के लिए चाहिए जिनमें चेनें कमज़ोर हैं: खोज, समुच्चयन, ऑफ़-चेन डेटा।

### क्या मैं wagmi या RainbowKit इस्तेमाल कर सकता हूँ?

हाँ। उन्हें पहले स्निपेट वाली वही चेन परिभाषा दीजिए। वे अधिकतर ऊपर दिखाए कनेक्शन और नेटवर्क-स्विच तर्क को ही लपेटते हैं, और सौंपने से पहले उसे एक बार समझना सार्थक है।

### टोकन बैलेंस कैसे दिखाऊँ?

टोकन कॉन्ट्रैक्ट पर `balanceOf` बुलाइए और उसके अपने `decimals()` से प्रारूपित कीजिए। दशमलव की संख्या कभी मत मानिए — [Nura Chain पर ERC-20 बनाना](/blog/create-an-erc-20-token-on-nura-chain) बताता है कि यह अनुमान यहाँ ख़ासकर क्यों महँगा है।

### बिना ख़र्च किए परीक्षण कैसे करूँ?

पढ़ने के रास्तों को धन चाहिए ही नहीं। लिखने के लिए थोड़े बैलेंस वाला फेंकने योग्य खाता लीजिए, और हर परिणाम एक्सप्लोरर पर पुष्ट कीजिए।

## आगे कहाँ जाएँ

अगर आपने वह कॉन्ट्रैक्ट अभी तैनात नहीं किया जिससे आपका इंटरफ़ेस बात करेगा, तो [Nura Chain पर स्मार्ट कॉन्ट्रैक्ट तैनात करना](/blog/deploy-a-smart-contract-on-nura-chain) से शुरू कीजिए।

आपके ऐप्लिकेशन ने असल में क्या किया, इसकी पुष्टि के लिए [Nura Chain एक्सप्लोरर कैसे इस्तेमाल करें](/blog/how-to-use-nura-chain-explorer) सही औज़ार है। और इस सबके पीछे नेटवर्क की बुनियाद के लिए [Nura Chain क्या है](/blog/what-is-nura-chain)।
