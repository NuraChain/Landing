dApp — это обычное веб-приложение с одним необычным свойством: оно никогда не хранит ключ пользователя. Оно читает из цепочки, а когда хочет что-то изменить, просит кошелёк подписать. Всё дальнейшее вытекает из этого разделения.

## Две половины

Чтение и запись — разные пути, и смешивать их это самая частая структурная ошибка.

**Чтение** идёт через ваше собственное RPC-соединение. Кошелёк ему не нужен, оно работает до того, как кто-либо подключится, и должно отрисовывать как можно большую часть интерфейса. Балансы, состояние контрактов, цены, история — всё это публично.

**Запись** идёт через кошелёк пользователя. Ей нужно его одобрение, её могут отклонить, и это единственная часть, которой подключение вообще требуется.

Стройте сначала путь чтения. dApp, показывающее пустую страницу до подключения кошелька, показывает пустую страницу каждому, кто как раз решает, стоит ли подключаться.

## Чтение

Используйте публичный клиент, направленный на эндпоинт, ровно как в статье [подключение к RPC Nura Chain](/blog/connect-to-nura-chain-rpc):

```javascript
import { createPublicClient, defineChain, http } from 'viem';

export const nura = defineChain({
    id: 1020,
    name: 'Nura Chain',
    nativeCurrency: { name: 'Nura', symbol: 'NURA', decimals: 18 },
    rpcUrls: { default: { http: ['https://rpc.nurachain.net'] } },
    blockExplorers: {
        default: { name: 'Nura Explorer', url: 'https://explorer.nurachain.net' }
    }
});

export const publicClient = createPublicClient({ chain: nura, transport: http() });
```

Этот объект — единственное определение сети для всего приложения. Импортируйте его повсюду, а не повторяйте значения.

## Подключение кошелька

Браузерный кошелёк внедряет провайдер по EIP-1193. Современный механизм обнаружения — EIP-6963: он объявляет каждый установленный кошелёк вместо драки за одну глобальную переменную, и его стоит использовать, если кошельков может оказаться несколько. Минимальный вариант:

```javascript
async function connect() {
    const provider = window.ethereum;

    if (provider === undefined) {
        throw new Error('No wallet found');
    }

    const [account] = await provider.request({ method: 'eth_requestAccounts' });

    return account;
}
```

Вызывайте это по клику, никогда при загрузке страницы. dApp, выбрасывающее окно кошелька в момент открытия страницы, — это dApp, которое закрывают.

## Как привести их в нужную сеть

Этот шаг большинство руководств пропускает, и именно на нём застревают живые пользователи. Подключённый кошелёк может находиться в любой сети. Попросите его переключиться и обработайте случай, когда он вообще не слышал о Nura Chain:

```javascript
const NURA_HEX = '0x3fc';

async function ensureNura(provider) {
    try {
        await provider.request({
            method: 'wallet_switchEthereumChain',
            params: [{ chainId: NURA_HEX }]
        });
    } catch (error) {
        // 4902: the wallet does not know this chain yet. Offer to add it, then
        // the switch above succeeds on the next attempt.
        if (error.code === 4902) {
            await provider.request({
                method: 'wallet_addEthereumChain',
                params: [{
                    chainId: NURA_HEX,
                    chainName: 'Nura Chain',
                    nativeCurrency: { name: 'Nura', symbol: 'NURA', decimals: 18 },
                    rpcUrls: ['https://rpc.nurachain.net'],
                    blockExplorerUrls: ['https://explorer.nurachain.net']
                }]
            });
        } else {
            throw error;
        }
    }
}
```

`0x3fc` — это 1020 в шестнадцатеричном виде, а кошельки хотят именно его. Ветка `4902` — то, что превращает «нажимаю, и ничего не происходит» в работающий первый опыт: это тот же запрос, что описан в [добавлении Nura Chain в кошелёк](/blog/add-nura-chain-to-your-wallet), только выпускает его ваша страница, а не человек вручную.

Слушайте также изменения, потому что пользователь может сменить сеть или аккаунт у вас за спиной:

```javascript
provider.on('chainChanged', () => window.location.reload());
provider.on('accountsChanged', (accounts) => setAccount(accounts[0] ?? null));
```

Перезагрузка по `chainChanged` груба, но корректна: она гарантирует, что не уцелеет никакое устаревшее состояние, привязанное к сети.

## Отправка транзакции

```javascript
import { createWalletClient, custom, parseEther } from 'viem';

const walletClient = createWalletClient({
    chain: nura,
    transport: custom(window.ethereum)
});

const hash = await walletClient.sendTransaction({
    account,
    to: '0xRecipient',
    value: parseEther('1')
});

const receipt = await publicClient.waitForTransactionReceipt({ hash });

if (receipt.status === 'reverted') {
    throw new Error('The transaction was included but reverted');
}
```

Обратите внимание на две вещи. Отправляет клиент кошелька, ждёт публичный клиент. И квитанция со статусом `reverted` — это транзакция, которая произошла, стоила газа и не сделала того, о чём просили; считать её успехом — ошибка, которую пользователи найдут.

## Состояния, которые действительно случаются

Обработайте все эти, потому что каждое встречается регулярно:

- **Кошелёк не установлен.** Покажите ссылку, а не сломанную кнопку.
- **Подключение отклонено.** Пользователь сказал нет. Тихо вернитесь в неподключённое состояние и не просите снова.
- **Не та сеть.** Предложите кнопку переключения вместо ошибки. Это крупнейший единичный источник растерянных пользователей.
- **Транзакция отклонена в кошельке.** Это не ошибка. Сбросьте состояние ожидания и продолжайте.
- **В ожидании.** Покажите хеш и ссылку на [Nura Explorer](https://explorer.nurachain.net), чтобы человек мог следить сам.
- **Откатилась.** Скажите об этом прямо. «Транзакция не удалась» с хешем лучше, чем крутящийся индикатор, который никогда не останавливается.

## Чего делать не следует

- **Не спрашивайте приватный ключ.** Никогда и ни по какой причине. dApp, которое его просит, неотличимо от фишинговой страницы.
- **Не запрашивайте неограниченные одобрения токенов по умолчанию.** Одобряйте ровно нужную сумму. Если большой лимит всё же нужен, скажите об этом в интерфейсе.
- **Не доверяйте chain ID, взятому из состояния.** Прочитайте его у провайдера перед отправкой чего-либо значимого.
- **Не держите весь интерфейс заложником подключения кошелька.** См. первый раздел.
- **Не опрашивайте цепочку на каждый рендер.** Кэшируйте чтения и разделяйте запросы в полёте.

## Частые вопросы

### Нужен ли бэкенд?

Ни для чтения, ни для записи в цепочку — и то и другое идёт прямо из браузера, что делает возможным разрешающий CORS эндпоинта. Бэкенд нужен для того, что цепочки делают плохо: поиск, агрегация, внецепочечные данные.

### Можно ли использовать wagmi или RainbowKit?

Да. Передайте им то же определение сети из первого фрагмента. В основном они оборачивают ту самую логику подключения и переключения сети, что показана выше, и её стоит один раз понять, прежде чем делегировать.

### Как показывать балансы токенов?

Вызывайте `balanceOf` у контракта токена и форматируйте по его собственному `decimals()`. Никогда не предполагайте число знаков — [создание ERC-20 в Nura Chain](/blog/create-an-erc-20-token-on-nura-chain) объясняет, почему именно здесь это предположение дорого обходится.

### Как тестировать, ничего не тратя?

Пути чтения не требуют средств вовсе. Для записи возьмите одноразовый аккаунт с небольшим балансом и подтверждайте каждый результат в обозревателе.
