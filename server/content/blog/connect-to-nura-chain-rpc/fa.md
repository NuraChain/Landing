هر کاری که یک برنامه با بلاک‌چین انجام می‌دهد از یک نقطه‌پایانی RPC می‌گذرد. این نوشته درباره نقطه‌پایانی نورا چین است: چه کاری می‌کند، چه کاری نمی‌کند، و چگونه کتابخانه‌های معمول را به آن نشانه بگیرید.

## نقطه‌پایانی

```text
https://rpc.nurachain.net
```

با JSON-RPC اتریوم روی HTTPS POST صحبت می‌کند و به شناسه زنجیره `1020` تعلق دارد. این مقدار دوم را به‌جای اینجا، از خود نقطه‌پایانی بخوانید:

```bash
curl -s https://rpc.nurachain.net -X POST \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'
```

`0x3fc` همان ۱۰۲۰ است. در هر کتابخانه زیر این عدد را صریح می‌دهیم، و این عمدی است: کلاینتی که بداند انتظار کدام زنجیره را دارد، وقتی نقطه‌پایانی چیز دیگری بگوید ادامه نمی‌دهد — و این یک استقرار خاموش روی شبکه اشتباه را به خطایی در زمان راه‌اندازی تبدیل می‌کند.

## نخستین درخواست، بدون نصب هیچ چیز

```bash
curl -s https://rpc.nurachain.net -X POST \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_blockNumber","params":[]}'
```

نتیجه‌ها به‌صورت کمیت‌های هگز برمی‌گردند نه اعداد ده‌دهی، و همین مدام آدم‌ها را غافلگیر می‌کند. `0x3aecc` برابر ۲۴۱٬۳۵۶ است. هر کتابخانه کلاینتی این تبدیل را برایتان انجام می‌دهد؛ `curl` خام نه.

## ethers.js

```javascript
import { JsonRpcProvider } from 'ethers';

const provider = new JsonRpcProvider('https://rpc.nurachain.net', {
    chainId: 1020,
    name: 'nura'
});

const [height, fees] = await Promise.all([
    provider.getBlockNumber(),
    provider.getFeeData()
]);

console.log(height, fees.maxFeePerGas);
```

دادن شبکه به‌عنوان آرگومان دوم دو کار می‌کند. یک رفت‌وبرگشت `eth_chainId` را در نخستین استفاده حذف می‌کند، و باعث می‌شود اگر نقطه‌پایانی زنجیره دیگری گزارش کرد، provider خطا بدهد. دومی همان چیزی است که ارزش داشتنش را دارد.

## viem

viem یک شیء chain می‌خواهد، و این جای خوبی است که همه مقادیر را در یک اعلان نگه دارید:

```javascript
import { createPublicClient, defineChain, http } from 'viem';

export const nura = defineChain({
    id: 1020,
    name: 'Nura Mainnet',
    nativeCurrency: { name: 'Nura Coin', symbol: 'NURA', decimals: 18 },
    rpcUrls: { default: { http: ['https://rpc.nurachain.net'] } },
    blockExplorers: {
        default: { name: 'Nura Explorer', url: 'https://explorer.nurachain.net' }
    }
});

const client = createPublicClient({ chain: nura, transport: http() });

console.log(await client.getBlockNumber());
```

همین شیء `nura` را بعداً به wagmi و به wallet client خود viem می‌دهید.

## web3.py

```python
from web3 import Web3

w3 = Web3(Web3.HTTPProvider("https://rpc.nurachain.net"))

assert w3.eth.chain_id == 1020, "not the chain you think you are on"
print(w3.eth.block_number)
```

نوشتن آن assert سه ثانیه وقت می‌گیرد و بیش از هر خط دیگری در این نوشته، استقرارها را نجات داده است.

## خواندن از مرورگر

نقطه‌پایانی هدرهای CORS بازی می‌فرستد، بنابراین یک صفحه می‌تواند مستقیم و بدون پراکسی اختصاصی شما آن را صدا بزند:

```javascript
const response = await fetch('https://rpc.nurachain.net', {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify({ jsonrpc: '2.0', id: 1, method: 'eth_blockNumber', params: [] })
});

const { result } = await response.json();
```

روشن باشیم که این چه چیزی را مجاز می‌کند. فراخوان‌های خواندنی از مرورگر کار می‌کنند. هر چیزی که به کلید خصوصی نیاز دارد اصلاً از این نقطه‌پایانی نمی‌گذرد — از کیف پول کاربر می‌گذرد، که مسیری کاملاً جداست و موضوع [ساختن یک dApp روی نورا چین](/blog/build-a-dapp-on-nura-chain) است.

## متدهایی که عمداً رد می‌شوند

از یک نقطه‌پایانی عمومی حساب بخواهید، جواب منفی می‌دهد:

```json
{"error":{"code":-32000,"message":"account unlock with HTTP access is forbidden"}}
```

این رفتار درست است نه قابلیتی که جا افتاده باشد. یک نود RPC عمومی هیچ کلیدی به نمایندگی از شما نگه نمی‌دارد، پس `eth_accounts`، `eth_sendTransaction` و `personal_*` چیزی برای کار کردن روی آن ندارند. نقطه‌پایانی‌ای که به آنها پاسخ می‌داد، نقطه‌پایانی‌ای بود که وجوه کسی را نگهداری می‌کند.

مسیر یک تراکنش امضاشده این است: محلی بسازیدش، محلی امضایش کنید، و بایت‌های امضاشده را با `eth_sendRawTransaction` بفرستید. هر کتابخانه‌ای وقتی به‌جای provider خالی یک wallet به آن بدهید، همین کار را برایتان می‌کند.

## نکته‌های عملی

- در هر رندر نظرسنجی نکنید. خواندن از زنجیره یک فراخوان شبکه است؛ چند ثانیه کشش کنید و یک درخواست در حال پرواز را میان فراخوانندگانی که هم‌زمان می‌رسند به اشتراک بگذارید.
- شناسه زنجیره را یک‌بار در زمان راه‌اندازی بخوانید و در صورت ناهمخوانی با صدای بلند شکست بخورید، نه در هر فراخوان.
- خواندن ناموفق را ناموفق در نظر بگیرید، نه صفر. موجودی‌ای که چون درخواست تایم‌اوت شد صفر نمایش داده می‌شود، از موجودی‌ای که خطا نشان می‌دهد بدتر است.
- قیمت گس را در کد ثابت نکنید. هنگام ارسال، داده کارمزد را بخواهید؛ [کارمزدها اینجا چگونه کار می‌کنند](/blog/nura-chain-evm-compatibility) را ببینید.

## پرسش‌های رایج

### آیا محدودیت نرخ وجود دارد؟

هر نقطه‌پایانی عمومی را محدودشده در نظر بگیرید، چه عددی اعلام کرده باشد چه نه، و برای همان طراحی کنید: کش، دسته‌بندی، و عقب‌نشینی در صورت شکست. برنامه‌ای که با هر ضربه کلید به یک نقطه‌پایانی مشترک می‌کوبد، دیر یا زود جایی throttle می‌شود، و این کار معقولی است از سوی یک اپراتور.

### آیا می‌توانم از وب‌سوکت یا اشتراک استفاده کنم؟

به‌جای فرض کردن، آزمایش کنید. اگر `eth_subscribe` در دسترس نبود، نظرسنجی `eth_blockNumber` در بازه‌ای معقول جایگزین قابل حملی است و در عمل همان چیزی است که بیشتر برنامه‌ها به آن می‌رسند.

### چرا تراکنش من هرگز تأیید نمی‌شود؟

علت معمول یک قیمت گس میخکوب‌شده است که از یک قالب باقی مانده و زیر کارمزد پایه فعلی است. به‌جایش هنگام ارسال داده کارمزد را بخوانید.

### می‌توانم نود خودم را اجرا کنم؟

هیچ‌چیز در این نوشته به استفاده از یک نقطه‌پایانی میزبانی‌شده وابسته نیست. برنامه‌ای که از نود خودتان بخواند تنها به یک URL متفاوت نیاز دارد، و همین ویژگی است که این معماری را ارزشمند می‌کند.
