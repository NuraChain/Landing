توکن ERC-20 نوع خاصی از دارایی نیست که زنجیره از آن خبر داشته باشد. یک قرارداد هوشمند معمولی است که نگاشتی از آدرس به موجودی نگه می‌دارد و مجموعه‌ای از توابع توافق‌شده را در دسترس می‌گذارد. هر چیز دیگری — نمایش در کیف پول‌ها، فهرست‌شدن در صرافی‌ها، نمایه‌شدن در کاوشگرها — از پیاده‌سازی درست همان رابط نتیجه می‌شود.

این نوشته نوشتن یکی، استقرارش روی نورا چین، و بخشی که بیشترین ضرر واقعی را می‌سازد را طی می‌کند: اعشار.

## ERC-20 دقیقاً چه چیزی را تعیین می‌کند

مشتی تابع و دو رویداد:

```solidity
function totalSupply() external view returns (uint256);
function balanceOf(address account) external view returns (uint256);
function transfer(address to, uint256 amount) external returns (bool);
function allowance(address owner, address spender) external view returns (uint256);
function approve(address spender, uint256 amount) external returns (bool);
function transferFrom(address from, address to, uint256 amount) external returns (bool);

event Transfer(address indexed from, address indexed to, uint256 value);
event Approval(address indexed owner, address indexed spender, uint256 value);
```

توابع `name()`، `symbol()` و `decimals()` در استاندارد اختیاری‌اند اما همه انتظارشان را دارند — کیف پولی که نمادی برای نشان‌دادن نداشته باشد، به‌جایش آدرس را نشان می‌دهد.

رویداد `Transfer` همان چیزی است که توکن را دیدنی می‌کند. کاوشگرها حافظه را پویش نمی‌کنند؛ رویدادها را نمایه می‌کنند. قراردادی که موجودی‌ها را جابه‌جا می‌کند بدون آنکه `Transfer` منتشر کند، توکنی است که هیچ چیز نمی‌تواند ببیندش.

## قرارداد

حساب‌وکتابش را خودتان ننویسید. از پیاده‌سازی بازبینی‌شده استفاده کنید:

```bash
npm install @openzeppelin/contracts
```

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract ExampleToken is ERC20 {
    constructor(uint256 initialSupply) ERC20("Example Token", "EXM") {
        _mint(msg.sender, initialSupply);
    }
}
```

این یک توکن کامل و کارآمد است. در برابر وسوسه افزودن ضرب، توقف، فهرست سیاه و کارمزد-روی-انتقال مقاومت کنید تا وقتی بتوانید دقیقاً بگویید چه کسی اجازه فراخوانی هرکدام را دارد، چون هر امتیاز افزوده راهی افزوده است برای آنکه توکن از دست دارندگانش گرفته شود.

## اعشار همان جایی است که گاز می‌گیرد

`decimals()` فراداده نمایشی است. بر حساب‌وکتاب اثری ندارد. قرارداد اعداد صحیح ذخیره می‌کند و `decimals` به رابط‌ها می‌گوید ممیز را کجا بگذارند.

با ۱۸ متعارف:

```text
1 token        = 1000000000000000000
0.5 token      =  500000000000000000
```

پس ضرب «یک میلیون توکن» یعنی:

```solidity
_mint(msg.sender, 1_000_000 * 10 ** 18);
```

دادن `1_000_000` به‌جای آن، یک‌میلیونیمِ یک‌میلیونیم توکن ضرب می‌کند، و این اشتباه تا وقتی کیف پولی نشانش ندهد نامرئی است.

تله آنجاست که فرض کنید یک نماد، تعداد اعشار را می‌رساند. چنین نیست، و نورا چین نمونه‌ای زنده دارد. قرارداد USDT پل‌شده اینجا ۱۸ اعشار گزارش می‌کند:

```bash
cast call 0x4E0DB0B1Da408faF5637202CF48b0bc7733bE6dC "decimals()(uint8)" \
  --rpc-url https://rpc.nurachain.net
```

USDT روی اتریوم از ۶ استفاده می‌کند. همان نماد، تعداد اعشار متفاوت، قرارداد متفاوت روی زنجیره متفاوت. هر یکپارچه‌سازی‌ای که «USDT یعنی ۶ اعشار» را در کد ثابت کند، اینجا به اندازه هزار میلیارد برابر خطا دارد. همیشه `decimals()` را از همان قراردادی بخوانید که واقعاً با آن حرف می‌زنید.

## استقرار

پیکربندی همان است که در [استقرار قرارداد هوشمند روی نورا چین](/blog/deploy-a-smart-contract-on-nura-chain) آمد — شناسه زنجیره `1020`، آدرس RPC برابر `https://rpc.nurachain.net`. اسکریپت استقرار تنها در پاس‌دادن یک آرگومان سازنده فرق می‌کند:

```javascript
import { ethers } from 'hardhat';

async function main() {
    const supply = ethers.parseUnits('1000000', 18);
    const token = await ethers.deployContract('ExampleToken', [supply]);

    await token.waitForDeployment();

    console.log('token at', await token.getAddress());
}

main().catch((error) => {
    console.error(error);
    process.exitCode = 1;
});
```

تابع `parseUnits` هست تا هرگز صفرها را با دست ننویسید. از آن استفاده کنید.

سپس تأیید کنید که قرارداد به‌عنوان یک توکن پاسخ می‌دهد نه صرفاً وجود دارد:

```bash
cast call 0xYourToken "symbol()(string)"      --rpc-url https://rpc.nurachain.net
cast call 0xYourToken "totalSupply()(uint256)" --rpc-url https://rpc.nurachain.net
```

## نمایش‌دادن آن در کیف پول

کیف پول‌ها توکن‌ها را خودکار کشف نمی‌کنند. دارنده یک‌بار آدرس قرارداد را زیر گزینه «افزودن توکن» یا مشابه آن وارد می‌کند، و کیف پول `symbol` و `decimals` را از خود قرارداد می‌خواند.

اگر کیف پولتان هنوز اصلاً به این شبکه نشانه نرفته، اول [افزودن نورا چین به کیف پول](/blog/add-nura-chain-to-your-wallet) می‌آید.

## دو ERC-20 که همین حالا روی این زنجیره‌اند

ارزش دارد به نمونه‌های واقعی نگاه کنید نه فقط به مال خودتان. هر دوی اینها قراردادهای معمولی ERC-20 مستقرشده روی نورا چین‌اند که دارایی‌های پل‌شده را نمایندگی می‌کنند:

```text
Bridge BNB    0xD4221Ad9772BF5bA7423a044bBBEe6af2154A5Fc
Bridge USDT   0x4E0DB0B1Da408faF5637202CF48b0bc7733bE6dC
```

آنها را به همان روشی که مال خودتان را پرسیدید بپرسید، یا در [کاوشگر نورا](https://explorer.nurachain.net) بازشان کنید. دقیقاً از این رو مفیدند که نمونه‌هایی نیستند که برای یک آموزش نوشته شده باشند — به `name()`، `symbol()`، `decimals()` و `totalSupply()` مثل هر توکن دیگری پاسخ می‌دهند، و نکته یک استاندارد همین است.

## اشتباه‌هایی که پول می‌برند

- **ضرب بدون جابه‌جایی اعشار**، همان‌طور که بالا آمد.
- **فرض اینکه نماد اعشار را می‌رساند.** `decimals()` را بخوانید. هر بار.
- **اعتماد به نماد.** هر کسی می‌تواند قراردادی مستقر کند که خودش را `USDT` بنامد. هویت، آدرس است؛ نام برچسبی است که مستقرکننده انتخاب کرده.
- **نگه‌داشتن مالکی که می‌تواند ضرب کند.** اختیار ضرب نامحدود یعنی عرضه هر چیزی است که دارنده کلید بگوید. اگر نگهش می‌دارید، علنی بگویید؛ اگر لازمش ندارید، از آن چشم بپوشید.
- **فرستادن توکن به خود قرارداد توکن.** لغزشی رایج، و معمولاً برگشت‌ناپذیر.

## پرسش‌های رایج

### آیا باید توکن را جایی ثبت کنم؟

نه. استقرارش همان انتشارش است. کیف پول‌ها و کاوشگرها آن را از زنجیره می‌خوانند. فهرست‌شدن در هر سرویس شخص ثالثی، رویه خود آن سرویس است.

### می‌توانم بعداً عرضه را تغییر دهم؟

فقط اگر قرارداد تابع ضرب یا سوزاندنی داشته باشد که عمداً گنجانده‌اید. نمونه بالا ندارد: عرضه‌اش هنگام ساخت ثابت می‌شود، که پیش‌فرض صادقانه است.

### نگه‌داشتن توکن چه هزینه‌ای دارد؟

استقرار یک‌بار گس می‌برد. پس از آن هر انتقال گسی می‌برد که فرستنده‌اش می‌پردازد — با NURA، نه با توکن شما.

### آیا خودم از صفر ERC-20 بنویسم؟

برای هیچ چیزی که ارزش نگه می‌دارد، نه. رابط آن‌قدر کوچک هست که ساده به نظر برسد و آن‌قدر لبه تیز دارد (مقادیر بازگشتی، مسابقه allowance، اعشار) که پیاده‌سازی بازبینی‌شده پیش‌فرض درست است.
