ERC-20 टोकन कोई ख़ास तरह की संपत्ति नहीं है जिसे चेन जानती हो। यह एक सामान्य स्मार्ट कॉन्ट्रैक्ट है जो पते-से-बैलेंस की मैपिंग रखता है और सहमत फ़ंक्शन का एक समुच्चय उजागर करता है। बाक़ी सब — वॉलेट में दिखना, एक्सचेंज पर सूचीबद्ध होना, एक्सप्लोरर में अनुक्रमित होना — उसी इंटरफ़ेस को ठीक से लागू करने से निकलता है।

यह लेख एक टोकन लिखने, उसे Nura Chain पर तैनात करने, और उस हिस्से से गुज़रता है जो सबसे ज़्यादा असली नुक़सान कराता है: दशमलव।

## ERC-20 असल में क्या तय करता है

मुट्ठी भर फ़ंक्शन और दो इवेंट:

```solidity
function totalSupply() external view returns (uint256);
function balanceOf(address account) external view returns (uint256);
function transfer(address to, uint256 amount) external returns (bool);
function allowance(address owner, address spender) external view returns (uint256);
function approve(address spender, uint256 amount) external returns (bool);
function transferFrom(address from, address to, uint256 amount) external returns (bool);

event Transfer(address indexed from, address indexed to, uint256 value);
event Approval(address indexed owner, address indexed spender, uint256 value);
```

`name()`, `symbol()` और `decimals()` मानक में वैकल्पिक हैं पर सर्वत्र अपेक्षित — जिस वॉलेट के पास दिखाने को प्रतीक न हो, वह उसकी जगह पता दिखा देगा।

`Transfer` इवेंट ही टोकन को दृश्य बनाता है। एक्सप्लोरर स्टोरेज नहीं खंगालते; वे इवेंट अनुक्रमित करते हैं। जो कॉन्ट्रैक्ट बैलेंस हिलाता है पर `Transfer` उत्सर्जित नहीं करता, वह ऐसा टोकन है जिसे कुछ भी देख नहीं सकता।

## कॉन्ट्रैक्ट

गणित ख़ुद मत लिखिए। समीक्षित कार्यान्वयन इस्तेमाल कीजिए:

```bash
npm install @openzeppelin/contracts
```

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract ExampleToken is ERC20 {
    constructor(uint256 initialSupply) ERC20("Example Token", "EXM") {
        _mint(msg.sender, initialSupply);
    }
}
```

यह पूरा, चलता-फिरता टोकन है। मिंटिंग, पॉज़, ब्लैकलिस्ट और ट्रांसफ़र-पर-शुल्क जोड़ने के लोभ का प्रतिरोध तब तक कीजिए जब तक आप ठीक-ठीक न कह सकें कि हर एक को कौन बुला सकता है, क्योंकि हर जोड़ा गया विशेषाधिकार टोकन को उसके धारकों से छीनने का एक और रास्ता है।

## दशमलव ही वह हिस्सा है जो काटता है

`decimals()` प्रदर्शन का मेटाडेटा है। गणित पर असर नहीं डालता। कॉन्ट्रैक्ट पूर्णांक रखता है, और `decimals` इंटरफ़ेस को बताता है कि बिंदु कहाँ लगाना है।

प्रचलित 18 के साथ:

```text
1 token        = 1000000000000000000
0.5 token      =  500000000000000000
```

तो "दस लाख टोकन" मिंट करने का अर्थ है:

```solidity
_mint(msg.sender, 1_000_000 * 10 ** 18);
```

इसके बजाय `1_000_000` देने से टोकन का दस-लाखवाँ का दस-लाखवाँ हिस्सा मिंट होता है, और यह ग़लती तब तक अदृश्य रहती है जब तक कोई वॉलेट उसे दिखा न दे।

जाल यह मान लेने में है कि प्रतीक दशमलव की संख्या बता देता है। नहीं बताता, और Nura Chain के पास इसका जीवंत उदाहरण है। यहाँ ब्रिज किया गया USDT कॉन्ट्रैक्ट 18 दशमलव बताता है:

```bash
cast call 0x4E0DB0B1Da408faF5637202CF48b0bc7733bE6dC "decimals()(uint8)" \
  --rpc-url https://rpc.nurachain.net
```

Ethereum पर USDT 6 इस्तेमाल करता है। वही टिकर, अलग दशमलव संख्या, अलग चेन पर अलग कॉन्ट्रैक्ट। जो भी एकीकरण "USDT यानी 6 दशमलव" कोड में जड़ देता है, वह यहाँ एक ट्रिलियन गुना ग़लत है। हमेशा `decimals()` उसी कॉन्ट्रैक्ट से पढ़िए जिससे आप असल में बात कर रहे हैं।

## तैनाती

कॉन्फ़िगरेशन वही है जो [Nura Chain पर स्मार्ट कॉन्ट्रैक्ट तैनात करना](/blog/deploy-a-smart-contract-on-nura-chain) में था — चेन आईडी `1020`, RPC `https://rpc.nurachain.net`। तैनाती स्क्रिप्ट केवल एक कंस्ट्रक्टर तर्क पास करने में भिन्न है:

```javascript
import { ethers } from 'hardhat';

async function main() {
    const supply = ethers.parseUnits('1000000', 18);
    const token = await ethers.deployContract('ExampleToken', [supply]);

    await token.waitForDeployment();

    console.log('token at', await token.getAddress());
}

main().catch((error) => {
    console.error(error);
    process.exitCode = 1;
});
```

`parseUnits` इसीलिए है कि आपको शून्य कभी हाथ से न लिखने पड़ें। इसे इस्तेमाल कीजिए।

उसके बाद पुष्टि कीजिए कि कॉन्ट्रैक्ट महज़ मौजूद नहीं है, बल्कि टोकन की तरह उत्तर देता है:

```bash
cast call 0xYourToken "symbol()(string)"      --rpc-url https://rpc.nurachain.net
cast call 0xYourToken "totalSupply()(uint256)" --rpc-url https://rpc.nurachain.net
```

## वॉलेट में दिखाना

वॉलेट टोकन अपने आप नहीं खोजते। धारक कॉन्ट्रैक्ट का पता एक बार "import token" या इसी तरह के विकल्प में जोड़ता है, और वॉलेट `symbol` तथा `decimals` कॉन्ट्रैक्ट से ही पढ़ लेता है।

अगर आपका वॉलेट अभी इस नेटवर्क पर लगा ही नहीं है, तो पहले [अपने वॉलेट में Nura Chain जोड़ना](/blog/add-nura-chain-to-your-wallet) आता है।

## दो ERC-20 जो पहले से इस चेन पर हैं

केवल अपना नहीं, असली टोकन देखना सार्थक है। नीचे के दोनों Nura Chain पर तैनात सामान्य ERC-20 कॉन्ट्रैक्ट हैं, जो ब्रिज की गई संपत्तियों का प्रतिनिधित्व करते हैं:

```text
Bridge BNB    0xD4221Ad9772BF5bA7423a044bBBEe6af2154A5Fc
Bridge USDT   0x4E0DB0B1Da408faF5637202CF48b0bc7733bE6dC
```

इन्हें उसी तरह पूछिए जैसे अपना पूछा था, या [Nura Explorer](https://explorer.nurachain.net) में खोलिए। ये ठीक इसलिए उपयोगी हैं क्योंकि ये किसी ट्यूटोरियल के लिए लिखे उदाहरण नहीं हैं — ये `name()`, `symbol()`, `decimals()` और `totalSupply()` का उत्तर किसी भी अन्य टोकन की तरह देते हैं, और मानक का मतलब यही है।

## वे ग़लतियाँ जो पैसे ले जाती हैं

- **दशमलव खिसकाए बिना मिंट करना**, जैसा ऊपर कहा।
- **यह मान लेना कि टिकर दशमलव बता देता है।** `decimals()` पढ़िए। हर बार।
- **प्रतीक पर भरोसा।** कोई भी ऐसा कॉन्ट्रैक्ट तैनात कर सकता है जो ख़ुद को `USDT` कहे। पहचान पता है; नाम वह लेबल है जो तैनात करने वाले ने चुना।
- **ऐसा मालिक रखना जो मिंट कर सके।** असीमित मिंट अधिकार का अर्थ है कि आपूर्ति वही है जो कुंजीधारक कहे। रखते हैं तो सार्वजनिक रूप से कहिए; ज़रूरत नहीं तो त्याग दीजिए।
- **टोकन को टोकन कॉन्ट्रैक्ट पर ही भेज देना।** आम चूक, और आमतौर पर अपरिवर्तनीय।

## आम सवाल

### क्या मुझे टोकन कहीं पंजीकृत कराना होगा?

नहीं। तैनात करना ही प्रकाशित करना है। वॉलेट और एक्सप्लोरर उसे चेन से पढ़ते हैं। किसी तीसरे पक्ष की सेवा पर सूचीबद्ध होना उस सेवा की अपनी प्रक्रिया है।

### क्या मैं बाद में आपूर्ति बदल सकता हूँ?

केवल तब जब कॉन्ट्रैक्ट में मिंट या बर्न फ़ंक्शन हो जिसे आपने जानबूझकर शामिल किया। ऊपर के उदाहरण में नहीं है: उसकी आपूर्ति निर्माण के समय तय हो जाती है, जो ईमानदार डिफ़ॉल्ट है।

### टोकन चलाने में क्या ख़र्च होता है?

तैनाती एक बार गैस लेती है। उसके बाद हर ट्रांसफ़र में गैस लगती है जो भेजने वाला चुकाता है — NURA में, आपके टोकन में नहीं।

### क्या मुझे अपना ERC-20 शून्य से लिखना चाहिए?

मूल्य रखने वाली किसी भी चीज़ के लिए नहीं। इंटरफ़ेस इतना छोटा है कि सरल लगे और उसमें इतनी तीखी धारें हैं (रिटर्न मान, allowance की दौड़, दशमलव) कि समीक्षित कार्यान्वयन ही सही डिफ़ॉल्ट है।
