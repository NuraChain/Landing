Токен ERC-20 — это не особый вид актива, о котором знает сама цепочка. Это обычный смарт-контракт, который хранит отображение адреса в баланс и предоставляет согласованный набор функций. Всё остальное — что кошельки его показывают, биржи листят, обозреватели индексируют — вытекает из корректной реализации этого интерфейса.

Здесь разбирается, как написать такой токен, развернуть его в Nura Chain и что именно вызывает больше всего реальных потерь: десятичные знаки.

## Что на самом деле задаёт ERC-20

Горстка функций и два события:

```solidity
function totalSupply() external view returns (uint256);
function balanceOf(address account) external view returns (uint256);
function transfer(address to, uint256 amount) external returns (bool);
function allowance(address owner, address spender) external view returns (uint256);
function approve(address spender, uint256 amount) external returns (bool);
function transferFrom(address from, address to, uint256 amount) external returns (bool);

event Transfer(address indexed from, address indexed to, uint256 value);
event Approval(address indexed owner, address indexed spender, uint256 value);
```

`name()`, `symbol()` и `decimals()` в стандарте необязательны, но их ждут повсеместно: кошельку, которому нечего показать вместо символа, придётся показать адрес.

Событие `Transfer` — это то, что делает токен видимым. Обозреватели не сканируют хранилище, они индексируют события. Контракт, который двигает балансы, не испуская `Transfer`, — это токен, которого никто не видит.

## Контракт

Не пишите арифметику сами. Возьмите проверенную реализацию:

```bash
npm install @openzeppelin/contracts
```

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract ExampleToken is ERC20 {
    constructor(uint256 initialSupply) ERC20("Example Token", "EXM") {
        _mint(msg.sender, initialSupply);
    }
}
```

Это уже полноценный рабочий токен. Соблазну добавить эмиссию, паузу, чёрные списки и комиссию при переводе стоит сопротивляться до тех пор, пока вы не сможете точно сказать, кому разрешено вызывать каждую из них: любая добавленная привилегия — это добавленный способ отобрать токен у держателей.

## Десятичные знаки — это то, что кусается

`decimals()` — метаданные отображения. На арифметику они не влияют. Контракт хранит целые числа, а `decimals` подсказывает интерфейсам, где ставить запятую.

При привычных 18:

```text
1 token        = 1000000000000000000
0.5 token      =  500000000000000000
```

Поэтому выпустить «миллион токенов» означает:

```solidity
_mint(msg.sender, 1_000_000 * 10 ** 18);
```

Передав вместо этого `1_000_000`, вы выпустите одну миллионную от одной миллионной токена, и ошибка останется невидимой, пока её не покажет кошелёк.

Ловушка — предполагать, что тикер задаёт число знаков. Это не так, и у Nura Chain есть живой пример. Здешний мостовой контракт USDT сообщает 18 знаков:

```bash
cast call 0x4E0DB0B1Da408faF5637202CF48b0bc7733bE6dC "decimals()(uint8)" \
  --rpc-url https://rpc.nurachain.net
```

А USDT в Ethereum использует 6. Тот же тикер, другое число знаков, другой контракт в другой сети. Любая интеграция, зашивающая «USDT — это 6 знаков», ошибается здесь в триллион раз. Всегда читайте `decimals()` у того контракта, с которым вы действительно разговариваете.

## Развёртывание

Конфигурация та же, что в статье [развёртывание смарт-контракта в Nura Chain](/blog/deploy-a-smart-contract-on-nura-chain): chain ID `1020`, RPC `https://rpc.nurachain.net`. Скрипт развёртывания отличается лишь передачей аргумента конструктору:

```javascript
import { ethers } from 'hardhat';

async function main() {
    const supply = ethers.parseUnits('1000000', 18);
    const token = await ethers.deployContract('ExampleToken', [supply]);

    await token.waitForDeployment();

    console.log('token at', await token.getAddress());
}

main().catch((error) => {
    console.error(error);
    process.exitCode = 1;
});
```

`parseUnits` существует затем, чтобы вы никогда не писали нули руками. Пользуйтесь ею.

Затем убедитесь, что контракт отвечает именно как токен, а не просто существует:

```bash
cast call 0xYourToken "symbol()(string)"      --rpc-url https://rpc.nurachain.net
cast call 0xYourToken "totalSupply()(uint256)" --rpc-url https://rpc.nurachain.net
```

## Как заставить кошелёк его показать

Кошельки не находят токены сами. Держатель один раз добавляет адрес контракта в пункте «импортировать токен» или подобном, а кошелёк читает `symbol` и `decimals` уже из самого контракта.

Если ваш кошелёк вообще ещё не направлен на эту сеть, сначала — [добавление Nura Chain в кошелёк](/blog/add-nura-chain-to-your-wallet).

## Ошибки, которые стоят денег

- **Эмиссия без сдвига на десятичные знаки**, как выше.
- **Предположение, что тикер задаёт знаки.** Читайте `decimals()`. Каждый раз.
- **Доверие символу.** Кто угодно может развернуть контракт, называющий себя `USDT`. Личность — это адрес; имя — ярлык, который выбрал разворачивавший.
- **Сохранение владельца, способного эмитировать.** Неограниченное право эмиссии означает, что эмиссия равна тому, что скажет держатель ключа. Оставляете — заявите об этом публично; не нужно — откажитесь.
- **Отправка токенов на сам контракт токена.** Частая оплошность и обычно невосстановимая.

## Частые вопросы

### Нужно ли где-то регистрировать токен?

Нет. Развернуть его — значит опубликовать. Кошельки и обозреватели читают его из цепочки. Листинг в любом стороннем сервисе — это процедура самого сервиса.

### Можно ли потом изменить эмиссию?

Только если в контракте есть функция выпуска или сжигания, которую вы намеренно включили. В примере выше её нет: эмиссия фиксируется при создании, и это честное значение по умолчанию.

### Во сколько обходится работа токена?

Развёртывание один раз стоит газа. Дальше каждый перевод стоит газа, который платит отправитель, — в NURA, а не в вашем токене.

### Стоит ли писать свой ERC-20 с нуля?

Ни для чего, что хранит ценность. Интерфейс достаточно мал, чтобы казаться простым, и имеет достаточно острых углов (возвращаемые значения, гонка allowance, десятичные знаки), чтобы проверенная реализация была правильным значением по умолчанию.
