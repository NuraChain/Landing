استقرار روی نورا چین یعنی استقرار روی یک شبکه EVM، پس ابزارها همان ابزارهایی هستند که می‌شناسید. آنچه در پی می‌آید پیکربندی، یک قرارداد، مرحله استقرار، و — بخشی که بیشتر راهنماها از آن می‌گذرند — چگونگی تأیید اینکه واقعاً روی زنجیره نشسته است.

## پیش از شروع

سه چیز.

- یک حساب شارژشده. استقرار یک تراکنش است، تراکنش گس می‌خواهد، و گس با NURA پرداخت می‌شود. حساب خالی نمی‌تواند مستقر کند.
- کلید خصوصی‌ای که حاضرید در یک متغیر محیطی بگذارید. برای نخستین استقرار از کلیدی دورریختنی استفاده کنید، نه کلیدی که موجودی‌تان را نگه می‌دارد.
- Node.js و یکی از Hardhat یا Foundry.

هرگز کلیدی را کامیت نکنید. همه نمونه‌های زیر از محیط می‌خوانند، و فایلی که کلید را نگه می‌دارد باید پیش از آنکه چیز واقعی در آن باشد در `.gitignore` قرار بگیرد.

## پیکربندی Hardhat

```javascript
import { HardhatUserConfig } from 'hardhat/config';
import '@nomicfoundation/hardhat-toolbox';

const config: HardhatUserConfig = {
    solidity: {
        version: '0.8.24',
        settings: { optimizer: { enabled: true, runs: 200 } }
    },
    networks: {
        nura: {
            url: 'https://rpc.nurachain.net',
            chainId: 1020,
            accounts: process.env.DEPLOYER_KEY ? [process.env.DEPLOYER_KEY] : []
        }
    }
};

export default config;
```

سطر `chainId` تزئینی نیست. Hardhat آن را با آنچه نقطه‌پایانی گزارش می‌کند مقایسه می‌کند و اگر نخوانند ادامه نمی‌دهد، و همین بررسی است که جلوی رفتن یک استقرار به شبکه‌ای که قصدش را نداشتید می‌گیرد.

درباره نسخه سالیدیتی: برای هدفی جاافتاده کامپایل کنید نه تازه‌ترین نسخه موجود. کامپایلری تازه که به‌صورت پیش‌فرض نسخه‌ای از EVM را هدف بگیرد که شبکه هنوز نپذیرفته، بایت‌کدی می‌سازد که مستقر می‌شود و بعد رفتار عجیب نشان می‌دهد — و این شکستی به‌مراتب بدتر از خطای کامپایل است.

## قراردادی که ارزش استقرار دارد

چیزی با وضعیت، تا راهی برای فهمیدن اینکه کار می‌کند وجود داشته باشد:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract Registry {
    event Recorded(address indexed who, string note);

    mapping(address => string) private notes;

    function record(string calldata note) external {
        notes[msg.sender] = note;
        emit Recorded(msg.sender, note);
    }

    function noteOf(address who) external view returns (string memory) {
        return notes[who];
    }
}
```

آن رویداد برای بخش بعد اهمیت دارد: رویدادها همان چیزی‌اند که یک کاوشگر نمایه می‌کند، پس قراردادی که رویداد منتشر می‌کند قراردادی است که می‌توانید از بیرون راستی‌آزمایی‌اش کنید.

## استقرار

```javascript
import { ethers } from 'hardhat';

async function main() {
    const factory = await ethers.getContractFactory('Registry');
    const contract = await factory.deploy();

    await contract.waitForDeployment();

    console.log('deployed to', await contract.getAddress());
    console.log('tx', contract.deploymentTransaction()?.hash);
}

main().catch((error) => {
    console.error(error);
    process.exitCode = 1;
});
```

و سپس:

```bash
DEPLOYER_KEY=0xyourkey npx hardhat run scripts/deploy.ts --network nura
```

سطر `waitForDeployment` را نگه دارید. بدون آن اسکریپت یک آدرس چاپ می‌کند و پیش از استخراج تراکنش خارج می‌شود، و شما با آدرسی می‌مانید که ممکن است کد داشته باشد یا نداشته باشد.

## تأیید اینکه نشسته است

آدرسی که یک اسکریپت چاپ می‌کند یک پیش‌بینی است، نه یک واقعیت. از زنجیره بپرسید:

```bash
curl -s https://rpc.nurachain.net -X POST \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_getCode","params":["0xYourContract","latest"]}'
```

قرارداد مستقرشده رشته هگز بلندی برمی‌گرداند. نتیجه `0x` یعنی در آن آدرس کدی نیست — استقرار برگشت خورده، گس تمام کرده، یا به شبکه دیگری رفته است. همین یک فراخوان «کار کرد» را از «اسکریپت خطا نداد» جدا می‌کند، و این دو یکی نیستند.

سپس آدرس را در [کاوشگر نورا](https://explorer.nurachain.net) باز کنید و به تراکنش نگاه کنید. [خواندن کاوشگر](/blog/how-to-use-nura-chain-explorer) معنای فیلدها را می‌گوید.

## همین کار در Foundry

```bash
forge create src/Registry.sol:Registry \
  --rpc-url https://rpc.nurachain.net \
  --private-key $DEPLOYER_KEY
```

و برای بررسی پس از آن، بدون ترک ترمینال:

```bash
cast code 0xYourContract --rpc-url https://rpc.nurachain.net
cast chain-id --rpc-url https://rpc.nurachain.net
```

دومی باید `1020` چاپ کند. این را عادت کنید.

## گس و کارمزد

بلاک‌ها اینجا کارمزد پایه EIP-1559 دارند، پس بگذارید ابزارتان تخمین بزند و `gasPrice` را میخکوب نکنید. هم Hardhat و هم Foundry داده کارمزد را از نقطه‌پایانی می‌خوانند و به‌صورت پیش‌فرض تراکنش نوع ۲ می‌سازند؛ دلیل معمول اینکه یک استقرار بی‌استخراج معلق می‌ماند، قیمت گس ثابتی است که از پیکربندی پروژه‌ای دیگر کپی شده و زیر کارمزد پایه فعلی است. سازوکارش در [نورا چین چگونه بایت‌کد EVM را اجرا می‌کند](/blog/nura-chain-evm-compatibility) آمده است.

## شکست‌هایی که شناختنشان می‌ارزد

- **«insufficient funds for gas».** حساب NURA ندارد. اول شارژش کنید.
- **«invalid chain id» یا ناهمخوانی شبکه.** پیکربندی شما و نقطه‌پایانی اختلاف دارند. `eth_chainId` را بخوانید و پیکربندی را درست کنید.
- **تراکنش برای همیشه در انتظار می‌ماند.** کارمزد پایین، یا شکاف nonce از تراکنش گیرکرده پیشین روی همان حساب.
- **`eth_getCode` مقدار `0x` برمی‌گرداند.** استقرار موفق نبوده، هر چه اسکریپت چاپ کرده باشد. رسید تراکنش را بیابید و وضعیتش را ببینید.

## پرسش‌های رایج

### می‌توانم قراردادی را که روی زنجیره دیگری دارم مستقر کنم؟

معمولاً بله، بدون تغییر، به شرطی که آدرسی از آن شبکه دیگر را در خود ثابت نکرده باشد یا به سرویسی که اینجا نیست وابسته نباشد. خود بایت‌کد قابل حمل است.

### آیا همان آدرس زنجیره دیگر را می‌گیرد؟

فقط اگر از همان حساب و با همان nonce مستقر کنید، چون آدرس قرارداد از همین دو مشتق می‌شود. اگر می‌خواهید آدرس عمداً یکی باشد، از `CREATE2` با یک مستقرکننده قطعی استفاده کنید.

### چطور سورس را روی کاوشگر راستی‌آزمایی کنم؟

فرم راستی‌آزمایی کاوشگر را بررسی کنید. راستی‌آزمایی راحتی‌ای برای خواننده است نه ویژگی‌ای از خود قرارداد، پس قرارداد چه سورسش منتشر شده باشد چه نه یکسان کار می‌کند.

### آیا برای ارتقاپذیری از پراکسی استفاده کنم؟

فقط اگر واقعاً به آن نیاز دارید. پراکسی‌ها خطرهای چیدمان حافظه و یک کلید مدیر می‌آورند که ارزشمندترین چیز سامانه می‌شود. قرارداد تغییرناپذیری که می‌توانید دوباره مستقر کنید برای بیشتر پروژه‌ها ساده‌تر و امن‌تر است.
