Развернуть контракт в Nura Chain — значит развернуть его в EVM-сети, поэтому инструменты те же, что вы уже знаете. Дальше идут конфигурация, контракт, шаг развёртывания и та часть, которую большинство руководств пропускает: как убедиться, что оно действительно попало в цепочку.

## Перед началом

Три вещи.

- Пополненный аккаунт. Развёртывание — это транзакция, транзакции стоят газа, а газ оплачивается в NURA. Пустой аккаунт развернуть ничего не может.
- Приватный ключ, который вы готовы положить в переменную окружения. Для первого развёртывания возьмите одноразовый ключ, а не тот, на котором лежит баланс.
- Node.js и либо Hardhat, либо Foundry.

Никогда не коммитьте ключ. Все примеры ниже читают его из окружения, а файл, который его хранит, должен попасть в `.gitignore` раньше, чем в нём окажется что-то настоящее.

## Конфигурация Hardhat

```javascript
import { HardhatUserConfig } from 'hardhat/config';
import '@nomicfoundation/hardhat-toolbox';

const config: HardhatUserConfig = {
    solidity: {
        version: '0.8.24',
        settings: { optimizer: { enabled: true, runs: 200 } }
    },
    networks: {
        nura: {
            url: 'https://rpc.nurachain.net',
            chainId: 1020,
            accounts: process.env.DEPLOYER_KEY ? [process.env.DEPLOYER_KEY] : []
        }
    }
};

export default config;
```

Строка `chainId` — не украшение. Hardhat сверяет её с тем, что сообщает эндпоинт, и отказывается продолжать при расхождении; именно эта проверка не даёт развёртыванию уйти в сеть, которую вы не имели в виду.

О версии Solidity: компилируйте под устоявшуюся цель, а не под самый свежий доступный релиз. Новый компилятор, по умолчанию нацеленный на версию EVM, которую сеть ещё не приняла, выдаёт байт-код, который разворачивается, а затем ведёт себя странно, — и это отказ куда худший, чем ошибка компиляции.

## Контракт, который стоит развернуть

Что-то с состоянием, чтобы было чем проверить, что он работает:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract Registry {
    event Recorded(address indexed who, string note);

    mapping(address => string) private notes;

    function record(string calldata note) external {
        notes[msg.sender] = note;
        emit Recorded(msg.sender, note);
    }

    function noteOf(address who) external view returns (string memory) {
        return notes[who];
    }
}
```

Событие важно для следующего раздела: именно события индексирует обозреватель, поэтому контракт, который их испускает, — это контракт, проверяемый снаружи.

## Развёртывание

```javascript
import { ethers } from 'hardhat';

async function main() {
    const factory = await ethers.getContractFactory('Registry');
    const contract = await factory.deploy();

    await contract.waitForDeployment();

    console.log('deployed to', await contract.getAddress());
    console.log('tx', contract.deploymentTransaction()?.hash);
}

main().catch((error) => {
    console.error(error);
    process.exitCode = 1;
});
```

Затем:

```bash
DEPLOYER_KEY=0xyourkey npx hardhat run scripts/deploy.ts --network nura
```

Строку `waitForDeployment` стоит сохранить. Без неё скрипт печатает адрес и завершается до того, как транзакция попадёт в блок, и у вас остаётся адрес, по которому кода может и не оказаться.

## Убедиться, что оно попало в цепочку

Адрес, напечатанный скриптом, — это предсказание, а не факт. Спросите цепочку:

```bash
curl -s https://rpc.nurachain.net -X POST \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_getCode","params":["0xYourContract","latest"]}'
```

Развёрнутый контракт возвращает длинную шестнадцатеричную строку. Результат `0x` означает, что кода по этому адресу нет: развёртывание откатилось, кончился газ или ушло в другую сеть. Один этот вызов отделяет «сработало» от «скрипт не бросил исключение», а это не одно и то же.

Затем откройте адрес в [Nura Explorer](https://explorer.nurachain.net) и посмотрите транзакцию. Статья [как читать обозреватель](/blog/how-to-use-nura-chain-explorer) объясняет значения полей.

## То же самое в Foundry

```bash
forge create src/Registry.sol:Registry \
  --rpc-url https://rpc.nurachain.net \
  --private-key $DEPLOYER_KEY
```

И проверка после, не покидая терминала:

```bash
cast code 0xYourContract --rpc-url https://rpc.nurachain.net
cast chain-id --rpc-url https://rpc.nurachain.net
```

Вторая команда должна напечатать `1020`. Сделайте это привычкой.

## Газ и комиссии

Блоки здесь несут базовую комиссию по EIP-1559, поэтому дайте инструментам оценить её, а не прибивайте `gasPrice`. И Hardhat, и Foundry читают данные о комиссии у эндпоинта и по умолчанию строят транзакцию второго типа; обычная причина, по которой развёртывание висит невключённым, — зашитая цена газа, скопированная из конфигурации другого проекта и оказавшаяся ниже текущей базовой комиссии. Механика — в статье [как Nura Chain исполняет байт-код EVM](/blog/nura-chain-evm-compatibility).

## Отказы, которые стоит узнавать

- **«insufficient funds for gas».** На аккаунте нет NURA. Сначала пополните.
- **«invalid chain id» или несовпадение сети.** Ваша конфигурация и эндпоинт расходятся. Прочитайте `eth_chainId` и поправьте конфигурацию.
- **Транзакция висит вечно.** Слишком низкая комиссия или разрыв в nonce из-за более ранней застрявшей транзакции с того же аккаунта.
- **`eth_getCode` возвращает `0x`.** Развёртывание не удалось, что бы ни напечатал скрипт. Найдите квитанцию транзакции и проверьте её статус.

## Частые вопросы

### Можно ли развернуть контракт, который у меня уже есть в другой сети?

Обычно да, без изменений, при условии что он не зашивает адрес из той сети и не зависит от сервиса, которого здесь нет. Сам байт-код переносим.

### Получит ли он тот же адрес, что и в другой сети?

Только если разворачивать с того же аккаунта и на том же nonce, потому что адрес контракта выводится именно из этих двух. Используйте `CREATE2` с детерминированным деплойером, если совпадение адреса нужно намеренно.

### Как верифицировать исходники в обозревателе?

Поищите в обозревателе форму верификации. Верификация — удобство для читателя, а не свойство контракта, так что он работает одинаково независимо от того, опубликованы ли исходники.

### Стоит ли использовать прокси ради обновляемости?

Только если это действительно нужно. Прокси добавляют опасности с раскладкой хранилища и админский ключ, который становится самой ценной вещью в системе. Неизменяемый контракт, который можно развернуть заново, для большинства проектов проще и безопаснее.
