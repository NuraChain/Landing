「EVM 兼容」几乎出现在过去五年里每一条新链的首页上，而它被用得足够宽松，值得把话说准。本文讲的是这个说法在 Nura Chain 上具体意味着什么、你自己能验证哪些，以及它并不提供什么。

## EVM 究竟是什么

以太坊虚拟机是一套栈式机器的规范。它定义了指令集、每条指令的 gas 成本、内存与存储模型，以及位于固定地址上的一组预编译合约。

Solidity 和 Vyper 并不编译成「以太坊」，它们编译成 EVM 字节码。正是这层分离，才使链与链之间的兼容成为可能：一份合约就是一段字节码加上描述如何调用它的 ABI，任何实现了同一指令集的机器都会以同样的方式执行这段字节码。

所以「EVM 兼容」是关于执行层的论断。它对共识、验证者、最终性或治理只字未提；一条链完全可以既是 EVM 兼容的，又在上述每一项上都与以太坊不同。

## Nura Chain 实现了什么

这条网络响应标准的以太坊 JSON-RPC 接口，而且你不用安装任何东西就能确认这一点。

```bash
curl -s https://rpc.nurachain.net -X POST \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"web3_clientVersion","params":[]}'
```

节点自报为 Go 实现，这正是大多数 EVM 网络所属的谱系——go-ethereum 及其衍生客户端。

从一个区块头里能读到的信息，比任何宣传页都多。取最新区块：

```bash
curl -s https://rpc.nurachain.net -X POST \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_getBlockByNumber","params":["latest",false]}'
```

返回的区块头带有 `baseFeePerGas`、值为 `0x0` 的 `difficulty`、全零的 `mixHash`，以及一个 `withdrawalsRoot`。这正是现代以太坊客户端在合并之后、以及 London 手续费市场变更之后所产生的形态，由此可以得出两个实际结论：手续费采用 EIP-1559 而非固定 gas 价格；`difficulty` 之类的工作量证明字段在这里没有意义——依据非零难度分支的代码会表现异常，就像它今天在以太坊上一样。

## 手续费遵循 EIP-1559

区块携带由协议设定的基础费，发送方在其上追加优先费。两者都可以读取：

```bash
curl -s https://rpc.nurachain.net -X POST \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_maxPriorityFeePerGas","params":[]}'
```

撰写本文时，基础费为 1 gwei，区块 gas 上限为 150,000,000。这两个值都应当在运行时读取，而不是写死在代码里——`eth_feeHistory` 和各类库的手续费估算正是为此而生，而把 `gasPrice` 写死的部署脚本，是交易迟迟不被打包的最常见原因。

由于手续费市场就是标准的那一套，`ethers`、`viem`、`web3.py` 以及近几年构建的任何钱包，在这里无需配置就能构造 type-2 交易。没有什么 Nura 特有的东西需要教给它们。

## 兼容性不会给你什么

这一部分通常会被略去。

- 它不会给你共享状态。你的地址在两条网络上都存在，因为它由同一把私钥派生，但余额、合约代码和历史是彼此独立的账本。发往「另一条链上同一地址」的资产，并没有在两者之间移动。
- 它不会给你共享合约。在以太坊上部署的合约并没有部署在这里。你要重新部署，而且会得到不同的地址，除非你刻意使用确定性部署器。
- 它不会给你以太坊的安全模型或验证者集合。那些是共识属性，而 EVM 兼容是关于执行的论断。
- 它不保证 gas 成本永远一致。各条链按自己的节奏采纳 EVM 升级，因此在一条链上便宜的合约，在另一条上未必如此。

现实中的大部分损失，都源于把第一条当作理所当然，单凭这一点它就值得再说一遍。

## 如何自己核实这些

上面每一条论断都只隔着一次请求，而这正是重点。一条能如实回答 `eth_chainId`、`eth_getBlockByNumber` 和 `web3_clientVersion` 的链，你大约一分钟就能刻画清楚，而不必信任任何一份文档页面——包括本页。

值得养成的习惯是：在部署任何有价值的东西之前，先从你即将使用的端点读取链 ID，再和你框架配置里声称的那个对照。两者不一致的情况比你以为的更常见，通常是因为配置从别的项目里抄了过来。

## 常见问题

### 我能原样部署一份现有的 Solidity 合约吗？

通常可以，前提是它不依赖某个特定的链 ID、不依赖写死在另一条网络上的合约地址、也不依赖这里并不存在的预言机。真正的摩擦来自这三点，而不是字节码本身。

### 我应该以哪个 Solidity 版本为目标？

选一个其 EVM 目标为本网络所支持的版本。稳妥的做法是编译到一个成熟的目标，而不是最新可用的那个，并在投入真实合约之前，先用一个可丢弃的合约试一次部署。

### gas 成本和以太坊一样吗？

指令成本来自 EVM 规范，所以形态是一致的。不同的是 gas 的价格，它由本网络自己的手续费市场决定，而非以太坊的。
