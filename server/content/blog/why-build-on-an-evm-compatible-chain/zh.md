「我们该不该建在一条 EVM 兼容链上？」这个问题通常被当作技术问题提出。它其实主要是生态问题，而诚实地回答它，就要说清楚兼容性买到了什么、付出了什么代价，以及如何评判某一条具体的链，而不是评判整个类别。

## EVM 兼容究竟买到了什么

以太坊虚拟机是一个指令集有明确规范的执行环境。实现了它的链，就能运行为任何其他 EVM 链编译的字节码。由此产生五个实际结果。

**工具链早已存在。** Solidity、Hardhat、Foundry、ethers、viem、web3.py——它们面向的都不是某一条特定网络，而是 EVM。新增一条链是一条配置项，而不是一次移植。

**标准早已存在。** ERC-20、ERC-721 和 ERC-1155 是接口而非实现，所以你写的代币遵循的是每个钱包和浏览器都已经理解的惯例。你不需要请任何人去集成一套定制格式。

**审计人员早已存在。** 这一点常被低估。一条采用全新执行模型的非 EVM 链，有资格审查其合约的人非常有限，而安全审查恰恰是真正卡住「能否上线任何承载价值之物」的那道关。

**开发者早已存在。** 招一个懂 Solidity 的人，和招一个愿意去学一门只有四个项目在用的语言的人，是两个完全不同的问题。

**用户早已有钱包。** 有 MetaMask 的人只要添加一个网络——一分钟的事——就能用上你的应用，而不必安装新东西并搬迁私钥。

这些加在一起，与其说是技术优势，不如说是复利优势：所有 EVM 链共享同一套工具，因此对这些工具的改进会惠及所有链。

## 代价是什么

兼容并不免费，而兜售它的文章很少这么说。

**你继承了 EVM 的局限。** 一台 256 位字长、存储相对昂贵的机器，并不是今天有人从零开始会选的设计。那些做出不同选择的非 EVM 链，是有实实在在理由的。

**你在一个拥挤的类别里竞争。** 如果你的链运行的字节码和所有别的链一样，那么执行层就不是你的差异点，你最好在别处有一个——手续费、最终性、治理，或某个具体应用。

**你也继承了 EVM 已知的失效模式。** 重入、授权竞态、整数处理、抢跑。应对它们的工具之所以成熟，正是因为这些风险被充分记录过，这确实是优势，但风险本身依然在。

**碎片化是真实存在的。** 同一个地址出现在许多链上、同一个代号指向不同合约、外观相同的代币却有不同的小数位。多链系统中用户的大部分损失，来自这一类混淆，而不是密码学失效。

## 与非 EVM 链相比

诚实的总结是：EVM 兼容优化的是「到第一次部署的时间」和「借用一套现成生态」。而一条为特定目的打造的非 EVM 链，优化的是它被设计来擅长的那件事，代价是每一件工具都要自建或引入。

如果你项目的价值在应用而不在新颖的执行语义——大多数项目都是如此——那么 EVM 的生态通常是更有力的论据。如果你需要的是 EVM 确实无法表达的东西，那么兼容性就是不该接受的约束。

## 如何评估一条具体的 EVM 链

这才是值得留存的部分，因为它适用于任何链，且大约只花十分钟。下面每一项检查，问的都是网络关于自身会作答的问题，而不是它宣传材料里的主张。

1. **链 ID 与文档所述是否一致？** 用 `eth_chainId` 去问端点。文档会过时，端点不会在这件事上撒谎。
2. **它跑的是哪个客户端？** `web3_clientVersion` 告诉你谱系，而谱系告诉你该预期哪些 EVM 升级。
3. **区块头长什么样？** `eth_getBlockByNumber` 会揭示是否有 EIP-1559 基础费、形态是否为合并后、gas 上限是多少。这比一份功能清单信息量大得多。
4. **实际出块时间是多少？** 比较一千个区块的时间戳，而不是采信一个标题数字。
5. **浏览器能否直接读取？** 宽松的 CORS 决定了你的前端是否还需要自建代理。
6. **有没有能用的区块浏览器？** 不是为了心安，而是为了排错。一条你无法查验的链，是一条你无法在生产环境里支撑的链。
7. **你能自己跑节点吗？** 如果答案是否定的，那么那条链上的每个应用，都将永久依赖别人的基础设施。
8. **什么是被拒绝的？** 一个拒绝 `eth_accounts` 的公共端点，行为是正确的。会响应它的那个，则是在保管私钥，这是危险信号。

## 同一份清单，实际跑一遍

把它跑在 Nura Chain 上，好让方法具体而非抽象：

```bash
curl -s https://rpc.nurachain.net -X POST \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'
```

它返回 `0x3fc`，即 1020，与该网络文档所述一致。`web3_clientVersion` 报告的是一个 Go 实现。区块头带有 `baseFeePerGas`、值为零的 `difficulty` 和一个 `withdrawalsRoot`，所以手续费是 EIP-1559，形态是合并之后的。区块大约每三秒产生一个。端点发送宽松的 CORS 头，页面因此可以直接从中读取；它还以明确的错误拒绝 `eth_accounts`——这正是公共节点应有的行为。

这些都不足以让任何一条链成为你项目的正确选择。但它意味着你可以在几分钟内刻画一条链，而不是去读一份白皮书，而这个习惯正是本节的要点。[Nura Chain 如何执行 EVM 字节码](/blog/nura-chain-evm-compatibility)把同样的内容讲得更细。

## 常见问题

### EVM 兼容和「是一条 Layer 2」是一回事吗？

不是。Layer 2 讲的是安全性从何而来——结算到另一条链上。EVM 兼容讲的是合约如何执行。一条链可以是其中之一、两者皆是，或者两者都不是。

### 我的以太坊合约能原样运行吗？

通常可以，前提是它没有写死某个链 ID、没有引用只存在于另一条网络上的合约地址、也不依赖尚未部署的预言机。真正的摩擦来自这三点，而不是字节码。

### 兼容是否意味着我的资产能在链之间移动？

不。这正是代价最高的那个误解。同一个地址之所以到处都存在，是因为它由你的私钥派生；但余额和合约在每条链上都是各自独立的账本。要在它们之间转移价值，需要跨链桥，而那是一套有其自身风险的系统。

### 试一试要花多少钱？

在一条低手续费的链上部署一份可丢弃的合约，成本极低，却能回答再多阅读都答不了的问题。[在 Nura Chain 上部署智能合约](/blog/deploy-a-smart-contract-on-nura-chain)从头到尾大约二十分钟。
