Nura Chain 是一条运行以太坊虚拟机（EVM）的公链。它以链 ID `1020` 标识，每三秒产出一个区块，采用 EIP-1559 费用市场为交易定价，并以其原生代币 NURA 支付计算费用。围绕这条网络的有一款自托管钱包、一个区块浏览器、一个兑换界面和一座桥，如今均已可用。

本文档是这条网络的参考性说明：它是什么、如何运作、它的代币有何用途、供应量如何划分、围绕它存在哪些东西，以及读者可以对照链上数据核实而无需凭信任接受的内容有哪些。它同时面向三类读者：正在决定是否持有 NURA 的人、准备在这条网络上开发的人，以及只是想弄清自己眼前所见为何物的人。

## 1. 引言

大多数人初次接触一条新链，是通过钱包里一个索要五个参数的对话框，而他们粘贴这些参数时并不知道其中任何一项的含义。Nura Chain 正是为了提供相反的体验而打造的。本文档陈述的每一个数字，要么可以直接从链上读取，要么被明确标注为已公布的主张；而围绕这条网络的工具，正是更广泛的 EVM 生态早已在用的那些工具。

这个名字只指一样东西：网络本身。建立在它之上的产品——Nura Wallet、Nura Explorer、Nura Swap——在第 7 节中介绍，它们与其所服务的链是彼此独立的。任何支持自定义网络的 EVM 钱包都可以使用 Nura Chain；项目自己的钱包只是入口之一，而非唯一入口。

## 2. 设计原则

下文的一切都由四项选择所塑造。

- **熟悉的执行环境。** 网络原样运行 EVM，因此合约、库、密钥和地址都可以从以太坊直接沿用，无需修改。开发者在 Nura Chain 上的第一天，只是添加一条配置项，而不是一次重写。
- **默认自托管。** Nura Wallet 从不保管密钥，也无法转移余额。网络没有账户找回、没有冻结、没有任何特权支出路径；谁持有密钥，谁就持有代币。
- **先可核实，再谈信任。** 链 ID、出块间隔、费用市场以及每个区块生产者的身份，都可以通过公开 RPC 读取。凡是无法从链上读取的数字——总供应量是其中最重要的一例——本文档都会明确说明，而不是暗示它可以。
- **精简的组成，如实的描述。** 这条网络交付的组件比一个营销页面可能罗列的要少，而每一个组件在这里都连同其局限一并说明，包括那些令人不适的局限。

## 3. 网络

### 3.1 执行层：以太坊虚拟机

Nura Chain 执行 EVM 字节码。用 Solidity 或 Vyper 面向 EVM 编译的合约，在这里以与以太坊上相同的语义、相同的指令开销和相同的 20 字节地址空间运行。节点响应标准的以太坊 JSON-RPC 接口，因此 ethers.js、viem、web3.py、wagmi、Hardhat 和 Foundry 只需一个端点和一个链 ID 就能与之协作。

兼容性只是关于执行层的陈述。你在以太坊上控制的地址在这里同样归你，因为它由同一把 secp256k1 密钥派生——但余额、已部署的合约和历史记录是各自独立的账本。把资产发到「另一条链上的同一地址」，并不会让它在两者之间转移。第 9 节会回到这一点，因为大多数真实损失正是由此而来。

### 3.2 区块、时间与费用

网络每三秒封存一个区块。这个间隔是固定值而非目标值：相邻两个区块头的时间戳恰好相差三秒。链的第一个区块的时间戳为 2026 年 6 月 6 日 00:00 UTC。

交易采用 EIP-1559 费用市场定价。每个区块携带一个由协议设定的基础费，发送方在其上附加一笔优先费；每个区块头中的 `baseFeePerGas` 字段，以及 `eth_maxPriorityFeePerGas` 和 `eth_feeHistory` 方法，会把两者都暴露出来。截至本修订版，基础费为 1 gwei，区块 gas 上限为 150,000,000 gas。这两个值都应在运行时读取而不是硬编码，而这正是库的费用估算默认所做的事。

区块头具有现代以太坊客户端所产生的形态：`difficulty` 为零、`nonce` 为空、`mixHash` 为零，以及 Shanghai、Cancun 和 Prague 升级引入的字段——`withdrawalsRoot`、`parentBeaconBlockRoot`、`blobGasUsed` 和 `requestsHash`。任何依据非零难度值进行分支、或指望工作量证明字段仍有意义的代码，在这里都会出错，正如它在今天的以太坊上一样。

### 3.3 区块生产

Nura Chain 不使用工作量证明；上述区块头字段已经排除了这种可能。区块由一个获得授权的区块生产者按上文所述的固定节奏封存。封存某个区块的账户记录在该区块的 `miner` 字段中，因此任何区块的生产者都是一项公开事实，而不是文档中的一句主张。

截至本修订版，抽样到的每一个区块都由同一个生产者账户封存。生产者集合的规模取决于网络如何运营，而非其执行层，本文档也不对此作出固定。任何相关变动都会通过第 11 节列出的项目渠道公布。

网络不通过 RPC 暴露单独的最终性信号。被打包进一个已封存的区块，就是钱包和浏览器所显示的确认；而由于区块按固定节奏产出，一笔已被打包的交易在一个间隔之内就能看到。

### 3.4 网络标识

以下是钱包或客户端库会向你索取的参数。它们与网站链信息卡片上的值相同，也与 Nura Wallet 存储的值相同。

- 网络名称：Nura Chain
- 链 ID：`1020`，钱包通常要求填写十六进制形式 `0x3fc`
- RPC 端点：`https://rpc.nurachain.net`
- 区块浏览器：`https://explorer.nurachain.net`
- 原生代币：Nura，代号 `NURA`，18 位小数
- 出块时间：3 秒

链 ID 不只是一个标签。依据 EIP-155，它会被签入每一笔交易，因此为链 1020 签名的交易无法在任何其他网络上重放，而为其他网络签名的交易在这里会被拒绝。在信任其余任何内容之前——包括本页面——它也是首先应当核对的值：

```bash
curl -s https://rpc.nurachain.net \
  -X POST -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'
```

返回是 `{"jsonrpc":"2.0","id":1,"result":"0x3fc"}`。支持 EIP-3085 的钱包可以通过一次请求接收上面的全部参数，网站上的「将 Nura Chain 添加到钱包」控件所做的正是这件事。

## 4. 原生代币

NURA 是这条网络的原生代币。它用来支付 gas：每笔交易都会消耗 gas，gas 以 NURA 计价，账户必须先有余额才能发出任何东西，包括它的第一次合约部署。这与 ether 在以太坊上的角色相同，最小单位同样是一枚代币的十亿分之一的十亿分之一。

由于它是原生资产而非合约，NURA 没有代币地址。如果某个页面为了添加这枚代币而索要「NURA 的合约地址」，它索要的是一个并不存在的东西；让余额出现的是添加网络这件事。ERC-20 代币在 Nura Chain 上以普通合约的形式存在，而 NURA 不属于其中之一。

## 5. 供应与分配

### 5.1 总供应量

已公布的总供应量为 1,000,000,000 NURA——十亿枚。

这是一个已公布的数字，而不是可以从链上读取的数字，这一区别至关重要。ERC-20 之所以暴露 `totalSupply()`，是因为它是一份自己记账的合约；而原生代币的发行存在于客户端配置和创世状态中，并不存在 `eth_totalSupply`。任何单个余额都可以用 `eth_getBalance` 读取；总量则不能。

本修订版有意不给出流通供应量。流通量取决于在某一时刻哪些份额被视为已解锁，而除非每一笔锁仓份额都存放在任何人都可以监看的公开地址上，否则那是一种判断而非测量。

### 5.2 分配

总量分为六个部分。各部分的百分比、由此推算的代币数量以及所声明的条款如下：

- **锁仓 — 40%，400,000,000 NURA。** 锁定一年。到期后如何处置将届时决定，且对这一部分的任何决定都需要获得至少 65% 网络投票的通过。
- **流动性 — 25%，250,000,000 NURA。** 在一年期内用于提供与管理流动性，目标是可用的交易流动性和更稳定的 NURA 生态。
- **社区 — 10%，100,000,000 NURA。** 在一年内分发给社区成员，面向那些以活动、参与、开发、推荐或其他有效贡献而非付费来推动网络成长的人。分配须经管理委员会审核并批准。
- **公开销售 — 10%，100,000,000 NURA。** 以合计 24,000 美元的价格在公开销售中发售，折合每枚 NURA 0.00024 美元。
- **金库 — 10%，100,000,000 NURA。** 在管理委员会监督下于一年期内分配，用于生态发展、基础设施、产品、合作以及项目的其他需要。
- **空投 — 5%，50,000,000 NURA。** 在一年期内以空投形式分发。接收者通过选定的渠道与社区确定，最终分配由管理委员会确认。

以上六项合计 100%。公开销售价格是该次销售的固定条件，而不是市场报价，不应被解读为对这枚代币的估值。

### 5.3 核实余额

网络上的每一个余额都是公开的。任何地址，包括项目方为某一份额公布的任何地址，任何人都可以读取：

```bash
curl -s https://rpc.nurachain.net -X POST \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_getBalance","params":["0xSomeAddress","latest"]}'
```

返回的是以 wei 为单位的十六进制值；除以 10^18 即得 NURA。Nura Explorer 显示的是同一个数字，两边都查是本文档自始至终推荐的习惯。

## 6. 治理

截至本修订版，这条网络声明了两条治理规则，两者都关乎上述分配，而非协议本身。

锁仓的 40% 供应量，未经至少 65% 网络投票通过，不得释放、改作他用或作出任何其他处置决定。这一门槛是针对供应量中最大单一份额的唯一约束性规则。

社区、金库和空投三个部分——合计占供应量的 25%——在管理委员会的审核与监督下分配，每一次分发都由该委员会确认。

此处不声明任何其他治理机制。协议自身的参数——出块间隔、费用市场、生产者集合——由网络运营方设定，本文档不描述针对这些参数的链上投票系统，因为并没有部署这样的系统。

## 7. 生态系统

### 7.1 Nura Wallet

Nura Wallet 是一款为这条网络打造的自托管钱包。私钥在设备上生成并保存，钱包自身无法动用余额。它的源代码和发布版本都公布在 GitHub 上。

它是一款原生应用，而不是浏览器扩展。已发布的构建包括：Android 版，同时提供 Google Play 上架版本和通用 APK；Windows 版，为 x64 安装程序；Linux 版，为 amd64 Debian 软件包。iOS 和 macOS 版本尚未发布。所有构建和架构都列在钱包的发布页面上。

由于它是一款应用，在钱包自带的应用内浏览器之外，网页没有可供注入的对象。因此网站通过两种方式与它通信：在该浏览器内部，通过 EIP-6963 的提供者公告；在其他任何地方，则通过 `nurawallet://` 深度链接，把请求送到应用并把结果返回给页面。其他任何 EVM 钱包都通过常规的 EIP-3085 添加链请求接入网络。

### 7.2 Nura Explorer

Nura Explorer 索引网络上的区块、交易和转账。它是确认一笔交易确实发生的地方，是读取合约代码与调用记录的地方，也是在每一个区块上都能看到第 3.3 节所述区块生产者的地方。它读取的正是 RPC 端点所服务的同一条链，这也正是两边都查值得花上十秒钟的原因。

### 7.3 Nura Swap

Nura Swap 是这条网络的兑换界面。它的资金池给出 NURA 相对于其封装表示的报价，网站显示的 NURA 价格正是这一报价。

该资金池规模很小，单笔交易即可大幅改变报价。这是来自单一资金池的市场报价，并非交易所上币，正因如此，本文档不给出任何价格。

### 7.4 桥

一座桥在 Nura Chain 上以普通 ERC-20 合约的形式铸造 BNB 和 USDT 的表示。两者都是铸造—销毁型代币，而非保险库：Nura 上之所以存在一个单位，只因为源链上锁定了一个单位。它们在 Nura 上的合约为：

- BNB：`0xD4221Ad9772BF5bA7423a044bBBEe6af2154A5Fc`
- USDT：`0x4E0DB0B1Da408faF5637202CF48b0bc7733bE6dC`

因此，跨入这条网络的价值就是每种代币的 `totalSupply()`，网站正是以此计算总锁仓价值。这个数字度量的是在 Nura 上铸造出的债权；只有在桥保持偿付能力且一比一足额背书时，它才等于抵押品。源链上的托管方余额才是权威的一方，也是细心的读者应当核对的数字。

## 8. 在 Nura Chain 上开发

Solidity 工具链中没有任何东西是专属于这条网络的。一次部署就是一条带有第 3.4 节中 RPC 端点和链 ID 的网络配置项，再加上足以支付 gas 的 NURA。在第一次部署之前，有三个容易卡住的地方值得了解。

- 从端点读取链 ID，并与框架配置进行比对。两者不一致的情况比想象中更常见，通常是因为配置是从另一个项目复制来的。
- 让库来估算费用。基础费和优先费都可以在运行时读取，而写死的 gas 价格是交易迟迟不被打包的最常见原因。
- 在别处部署过的合约在这里并未部署。除非刻意使用确定性部署器，否则重新部署会分配一个新地址；对其他网络上合约或预言机的任何硬编码依赖，都必须重新审视。

RPC 端点发送宽松的 CORS 头，因此浏览器中运行的页面可以直接从链上读取数据，无需中间服务器。项目博客提供了连接网络、部署合约和发行 ERC-20 的分步指南。

## 9. 安全与风险

- **自托管是一份责任。** 助记词一旦丢失就没有找回途径，在这条网络上如此，在任何网络上都如此；交易一经封存，任何一方都无法撤销。
- **链 ID 填错是资金丢失的方式。** 在把网络存入钱包之前，先对照端点核实 `1020`，并把任何页面——包括本页面——都当作有待核对的主张。
- **兼容不等于共享状态。** 资产不会因为被发到同一地址就在链之间转移。只有第 7.4 节中的桥能把 BNB 或 USDT 转入这条网络，而且仅限于那里所述的限制之内。
- **兑换报价很薄。** 从一个小资金池读出的价格不是估值，单笔交易就能改变它。
- **桥带有托管风险。** 铸造出的表示只有在源链侧托管方一比一持有抵押品时，才值其抵押品的价值。
- **有些数字是已公布的主张。** 总供应量和第 5 节中的分配条款无法通过 RPC 证实。凡项目方公布了分配地址的，其余额可以用第 5.3 节中的调用读取。
- **区块生产是集中的。** 第 3.3 节如实陈述了观测到的生产者集合，以便读者现在就能权衡，而不是事后才发现。
